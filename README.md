# T.E.C-OS 节点原型 MVP v2

把 T.E.C-OS（案件 A-001）的交互从「命令行 + 超链接」改成 **Nodes 式节点图**：**拖拽 = 合成**。

零依赖、真实 A-001 数据内嵌，**素材双构建**：`index.html` 走 `assets/` 外链（HTML 仅 ~310KB，音频可缓存可流式），`tecnode-standalone.html` 全内联（单文件，双击即玩、离线分发）。**没有改动 `chrisutada.github.io` 仓库里的任何文件。**

> 界面主题：复古单色系统风（灵感来自 PC-98 时代 OS / 早期 Windows 界面）——米白 + 墨色的单色世界，圆角细黑框窗口、中文像素字体（凤凰点阵体 Vonwaon Bitmap 12px，Haoyu Qiu / CC0）；唯一的彩色是台灯点亮时的暖黄光晕。主题纯 CSS 实现，交互逻辑与类名钩子未动。
>
> **桌布 = 暖象牙纸**：三层叠加做纸感 —— 细颗粒（`feTurbulence` 噪波，`soft-light` 混合，均值中性不压暗底色）＋ 零星深色纸屑（阈值化噪波，`multiply`，覆盖率约 1.3%）＋ 大面积色斑（三个 radial-gradient 表现纸张不匀），最后一层极淡的边缘压暗。噪波以内联 SVG data-URI 内嵌，无外部图片依赖。调参入口集中在 `:root` 的 `--paper-grain` / `--paper-fleck` 与 `#stage` 的 `background-*` 一组声明里。

## v2 相对 v1 的改动（核心）

| | v1（错的方向） | v2 |
|---|---|---|
| 拖拽 | 移动节点位置 | **拖 A 到 B 上 = 组合使用** |
| 布局 | 手工自由摆放 | 力导向自动布局，节点不用摆 |
| 场景 | 双击「下钻」，独立页面 | 双击**展开**，里面的东西掉到画布上、永久留在图上 |
| 合成 | 无 | 有：产出新节点 / 新场景，并**消耗**参与节点 |
| 密码 / 选项 | 无 | 全在节点上：双击木盒弹密码框输 0321、双击抽屉弹出左/右抽屉节点 |

## 操作

| 操作 | 效果 |
|---|---|
| **拖动节点** | **移动位置**（跟手）。松手落在空白处就停在那 —— **不会自动钉住**；要留住这个摆位就**右键钉住**它，否则下一次自动布局会把它重排走 |
| **右键点节点** | **钉住 / 取消钉住**（静默开关，**不弹任何提示**）。这是**唯一**的钉住入口 —— 拖动只移动、不再自动钉住。钉住有两个作用：自动布局不再挪它、所在场景折叠时也不收它。状态只在节点**左上角**挂一枚空心药丸「已固定」上体现（与右上角的通知类角标分开）—— 再右键一次即解除 |
| **拖到另一个节点上松手** | **组合**。命中则产出新节点/新场景并消耗参与节点；节点自己被弹回原位。**不弹任何结果提示条**（成功、失败都不弹）—— 效果靠画面自证：新节点当场冒出来、被消耗的节点当场消失；反应正文与获得/消耗只进 `SYS_LOGS`。**目标上写着前置零件的命令会先查门**：没装唱针时把黑胶拖到唱机上会被拦下（日志写「唱机上还没有装唱针，黑胶放上去也放不出声」），黑胶留在画布上 |
| **给节点装上零件**（唱机 ← 唱针） | 命令上写 `installs: true` 的 `useItem` 一旦成功，工具就被**装到这个节点上**：工具节点被消耗掉、装上的状态记在**目标节点**里（`n.installed`，进快照、跟着撤销 / 续档 / 续档回访走），详情窗写「**已装上 唱针**」。别的命令可以用 `requires: ["ITEMS_cz"]` 要求「那些零件得先装上」—— 详情窗会替玩家把条件写出来（未装上时显示「**待装上：唱针**」，和「光照条件」一个待遇）。两条入口（双击跑主命令 / 拖动组合）认同一道门 |
| **拖到已折叠的容器节点上**（场景 / 书桌 / 垃圾桶） | **拒绝**：折叠的容器不收东西，弹提示 `X 场景已折叠：先双击展开，或把节点拖到证物袋`（容器物品那一句省掉「场景」二字）。要收纳请用证物袋 / 线索册，或先双击展开再用 |
| **点详情窗正文里的虚线下划线** | **摘录**。文本物（纸条 / 笔记这类）的正文里，被数据点名的词 —— 纸条上的「7月4日」「槿杉」—— 渲染成**虚线下划线**；点一下就在画布上**长出目标节点 + 一条连回这张纸的边**（镜头自动带过去、节点带「新」角标、进撤销栈、也计入枢纽统计）。摘过的词**就地褪成灰、去掉下划线**，再点只把镜头带过去、不重复长。详情窗**留在原来那张纸上**，可以接着摘下一个词。纸上的字不再是「读完就完了」的死胡同 |
| **拖节点到 TEC（图标或窗内头像）** | **捕获 hiddenClue**：约 5~8 秒分析后给出结果 —— 有隐藏线索就落成画布上的线索节点（可自由拖动），没有则提示「没有可以捕获的线索」；分析期间窗内显示「分析中 · 标签」与进度条。真结局配方的前置。**节点上不再有「捕」小按钮** |
| 案件窗标题栏 **最小化 `–`**（收起） | 把案件缩成**桌面右下角的独立案件卡片**（`#case-dock`，170×56，显示案号 / 案名 / 「进度已保存 · 点此展开」）：先把进度（含镜头位置）存进本案的档 → 案件窗**带位移与缩放地收缩**、精确落到卡片中心（约 280ms）→ 窗口隐藏、卡片亮起。**不会弹案件地图。** 卡片**可拖动**（按住挪位置，拖完那一次单击不会误展开）；点卡片即从卡片位置放大展开、原位续档 |
| 案件窗标题栏 **关闭 `×`** | 把案件收进桌面左侧**「案件地图」图标**里：先存盘 → 窗口**直接离屏（不做收缩动画）**，那个图标打上**「已关闭」角标**。**不会弹案件地图。** 要拿回来：双击「案件地图」图标开出地图，点本案那行即从图标位置放大展开、原位续档 |
| 案件窗离屏（上面两种） | 顶栏那几个画布操作（适应窗口 / 撤销 / 重置 / 检查可达性）会被拦下并提示，不会去操作一个看不见的画布 |
| 桌面图标（在案件窗**左侧的桌面栏**里竖排，可拖动换位） | 功能入口统一为 OS 桌面图标：**单击 = 选中，拖动 = 移动，双击 = 打开应用窗口**，**拖节点到图标上 = 直达功能**。八个固定入口（推演器 / 档案 / 线索册 / 人物 / 证物袋 / TEC / 日志 / 案件地图）+ 两个**动态图标**（唱机装上唱针 → 播放器；结局遮罩上确认捕获真名 → 花园，都按状态挂进同一条站位队列，消失时队列自动补位）。图标属于**桌面层**，不在案件窗里 —— 案件窗只装节点画布 |
| 开场适性测试（首次启动） | `APTITUDE // 调查员适性测试`：登记姓名 → 三道五感倾向题 → **`AVATAR // 选择头像`**（详见下文头像库一节；领证页还留一条「换一张头像」退回去改）→ 生成 `INVESTIGATOR // 调查员证`（**竖版挂绳工牌式**三区卡纸：黑色头部色带 + 身份区【居中的 **156px 相框 / 144px 像素头像**，`image-rendering:pixelated` 整数放大 + 姓名/编号/等级】+ 倾向区 + 签发区【日期 + 旋转的**红色圆形核准印章**】，证件为全界面唯一圆角元素）→ 确认领证后窗口缩入**顶栏徽标**；徽标点击 = 回看证件（含 **`[ 更换头像 ]`** / 重新测试）；localStorage 持久化，之后启动直接进入案件 |
| ◈ 推演器 | 双击开 `INFERENCE // 推演器`（逻辑阵列）：**已归位的线索以与外部节点一致的卡片呈现**（`mx-chip node ent-node ent-clue`），按五感锚点分组（锚点不再显示五感文字，感官名只进 tooltip，排布交给五芒星本身）；拖线索节点入桌布、或拖到 ◈ 图标上，**自动归入它自己的感官槽** —— **归位 = 收进桌布：画布上那份线索跟着消失**（与拖进证物袋 / 线索册同一套 `stored` 机制，`storedIn = MATRIX`；图标角标显示已归位条数）。**把阵列内的卡片拖出桌布 = 取回画布**（落在松手那一点、带「新」角标；卡上不放 ×，拖出是唯一的回头路），类型不符拒绝。五感证据即**五芒星**的五个顶点（描线常显，`MX_ANCHORS` 按近似正五边形摆放，半径≈175px），中央执行者用 `assets/zxz.png` 头像居中枢，**长按 2.5 秒描出五芒星激活归因**——阵列线索与某结局配方精确匹配即触发**结局演出**（全屏步进放映，点击跳过，真结局有真名揭示） |

| ▦ 案件地图 | **双击 = `CASE MAP // 案件地图` 窗口**：列出各案件地址卡。当前案件标「当前」、案件窗收起时标「进入」，未解锁标「加密」（虚线灰显），已解锁但数据还没装载的标「待接入」。**只有在本案捕获「真名」（真结局）后，下一案地址才点亮**；解锁进度独立存档，不被「重置案件」清除。**点击已解锁且有数据的地址 = 展开/切案**：案件窗离屏时从它上次落下的地方（右下角卡片 / 「案件地图」图标）放大展开，开着别的案时案件窗淡出 → 换档 → 淡入，标题栏与顶栏同步换名，会话态（撤销栈 / TEC 对话 / 图标位置）清空，然后续上该案自己的存档（没有存档则全新开局）；刚进入过的地址会留一个红框点亮标记 |
| ❀ 花园（确认捕获真名后出现） | 结局遮罩上**亲手点下「确认捕获」**的那一刻，桌面长出**花园图标**，同时**执行者头顶挂出一枚种子对话框**（气泡里**只有一张种子图**，**拖拽把手就是那张图本身**——按白卡空白处拖不动；**种子不拖走对话框就不消失**——推理窗关了重开也按状态重建）。**拖进花园窗（或花园图标）= 下种**：**没有固定坛位，落在哪儿就种在哪儿**（株记住落点的百分比坐标），头顶对话框随之收走。**真实时钟约三分钟长成白花**（种子 → 嫩芽 → 展叶 → 舒叶 → 开花，45s 一档；株上只记「下种时刻」—— **关掉游戏再回来，花不会倒退**），跨过开花那一刻弹一枚 toast，图标角标显示「N 株」。**花草可以在花圃里随意拖动摆放**（不进撤销栈——摆放是装修不是破案进度）。下种进撤销栈（撤销把种子收回头顶）；重置 / 换案随 G 清空，图标与窗一并收；下种要案卷开着（与收纳同一道 `requireCase` 门） |

**多案件（每案一档 + 案件窗口化）**

**分层**：`#desktop`（桌面层）> `#case-win`（案件窗，只装 `#stage` 画布）+ `#icons` / `#case-dock`（收起后的案件卡片）/ `#log-win` / `#detail-win` / `#toast`（都是 `#case-win` 的**兄弟**，同挂在桌面层上）。桌面层左侧留出 100px 的**图标栏**，案件窗从 `left:100px` 起铺开。图标栏从桌面顶部（`top:16px`）开始竖排，间距 85px；桌面高度不够时自动压缩间距，保证最后一个图标不被 `#desktop{overflow:hidden}` 裁掉。第 6 个图标就是**「案件地图」**——它既开地图窗口，也接收被收起的案件（见下）。

- **一档一案**：离开一个案（切案 / 案件窗离屏）时，把当前案的 `G` 快照写进 localStorage `tec_case_<id>`（与撤销栈同一套序列化），回访时原样恢复 —— 节点位置、已捕获线索、逻辑阵列、结局记录全都各归各案。
- **案件窗离屏有两个落点，互斥**：都走同一个 `parkCase(p)`（先存盘 → 收缩动画 → 隐藏窗口 → 点亮落点），只是 `p` 不同 —— `stowCase()` = `parkCase("dock")`（标题栏 **`–` 收起**，落到右下角卡片 `#case-dock`），`closeCase()` = `parkCase("icon")`（标题栏 **`×` 关闭**，落到 `#map-icon .icon-glyph` 图标方块中心）。两者都先把进度（含镜头 `__view`）存进本案的档，**都不自动打开案件地图**。落点提示：卡片亮起 `.on` + 显示案号案名；图标打**「已关闭」角标**（`setCaseHeld(true)`，复用现有的 `.badge` 机制）。
- **要拿回来**：双击「案件地图」图标 → 地图窗口 → 点本案那行；或直接点右下角卡片。`caseParkedAt()` 记住它落在哪，`enterCase` 用 `caseMotionPlayIn(p)` 从那个落点放大展开，原位续档 —— 而不是重新 `fit()` 把整张图缩到最小。老存档没有 `__view` 就退回 `fit()`。
- **「案件地图」图标本来就可拖动**（它走通用的 `attachIcon`，和左侧其它图标同一套「单击选中 / 拖动换位 / 双击开窗」），所以"能拖"是白拿的；拖动时角标跟着走。
- **进入案件的三种情况**：已经开着本案 → 空操作；开着别的案 → 存旧案 + 换档；本来离屏 → 不存旧案，直接读档进入并从它上次落下的落点展开。
- **切案 / 案件窗离屏会清的**：撤销栈 `history`、TEC 对话历史 `tecHistory`、桌面图标位置。**不会清的**：解锁进度 `tec_progress`、顶栏的调查员证 `tec_investigator`。
- **「重置」只清当前案**：重置会连同本案存档 `tec_case_<id>` 一起删掉，别的案的档不受影响。
- **案件数据要自己报名字**：案件 JSON 的 `config` 里可写 `caseTitle`（地图与案件窗显示的案名）、`caseNote`（地图副标题）。`config` 里没写时退回 `CASES` 注册表里的占位名（A-002 现在是「？？？？？？」）。
- **地图行五档状态**：`加密`（未解锁）/ `进入`（本案，案件窗离屏）/ `当前`（本案，案件窗开着）/ `待接入`（已解锁但数据没装载）/ `可进入`（别的已解锁案）。`lastEnteredCase` 记着上次进入的案件，那一行带红框点亮。

## 去重规则（一段文本只在一个地方出现）

几个界面各管一类信息，互不逐字复读：

| 界面 | 职责 | 不再做的事 |
|---|---|---|
| 🗔 **SCENE_FEED 叙事卡** / 💬 对话窗 | 承载**正文**（场景叙事、角色台词） | — |
| ▨ **提示条（toast）** | 只承载**系统播报**（切案 / 重置、线索捕获、推演器与 TEC 的守卫提示、拖拽落点提示） | 不承载**任何物品信息**；也不承载**节点的动作结果 / 错误提示** —— 含**组合结果**（成功与失败都不弹） |
| ≡ **SYS_LOGS 日志** | 只记**结果**（捕获 / 结局 / 解锁 / 组合 / 使用 / 前往 / 失败；对话只记「这句话给了线索」） | 不再镜像浮层全文；也**不记过程** —— 展开收起容器、收纳取回、叙事卡放映、撤销 / 重置、离屏、可达性统计、**对话台词本身**一律不写 |
| ▤ **DETAIL 详情窗** | 只放三样：**简介 / 状态 / 来源** | 不列任何**结构关系**（容器里装着什么、谁的正文指向它、它跟谁有反应）；不复读别处已有的正文（场景正文仍只在叙事卡）；**不承载动作 / 错误提示** |

判定规则（2026-10-14 收口）：

> **详情窗只回答三个问题 —— 它是什么（简介）、它现在怎么样（状态）、它从哪来（来源）。**
> 凡是「玩家该自己动手试出来」的东西一律不写：展开容器才知道里面有什么、组合才知道谁跟谁配、
> 拖给 TEC 分析才知道场景里藏了什么线索。把这些写在详情窗里等于直接递答案。
>
> **唯一的例外是「状态」里的使用条件**（要光 / 要零件 / 开关与否）：那是**防瞎试的前馈**，不是答案 ——
> 它只说「需要什么」，绝不说「跟谁配」。所以手电筒会写「先点亮它，才能照亮黑暗里的东西」，
> 但黑影**不会**写「与这些东西存在反应：手电筒」。

| 节点 | 简介 | 状态 | 来源 |
|---|---|---|---|
| 场景 | 无 —— 正文只在叙事卡；展开后底部给「[ 重看场景叙事 ]」 | 已探索 / 未探索 | —（场景之间是叙事链接，不是「谁装下了谁」，且 `homeScene` 会被最后一次展开的宿主覆盖，写出来是随机的） |
| **容器物品**（书桌 / 垃圾桶） | 无 —— 同场景，「[ 重看叙事 ]」 | 已探索 / 未探索 | 生它的那个容器 |
| 物品（**不论有没有命令**） | `desc`（**唯一出口**）；文本物里被 `excerpts` 点名的词渲染成可点下划线 | 使用条件（光线 / 开关 / 装配）；没有条件就不写这行 | 生它的那个容器 |
| 线索 | `desc` | 已捕获 / 未捕获 · 视觉 / 听觉 / 触觉 … | 出它的那个场景 |
| 角色 | 一句话身份 | 可对话 / 已聊完（状态词，不显示条数） | 遇见他的场景 |

分类行只写 `物品 / 场景 / 角色 / 线索`，**不再带内部 `key`**（调试时看 `__dump()`）。

> **节点的「动作结果 / 错误提示」一律不显示**（既不入详情窗，也不弹提示条）：交互的影响本来就是**画面上自证**的 ——
> 台灯点亮看得见、组合后新节点会冒出来、线索会落盘、场景会展开；「条件不足」也就是**什么也没发生**。
> **组合结果曾经是唯一的例外**（成功弹一张「工具 → 目标 / 反应正文 / 获得：… 消耗：…」的条），现已去掉：
> 「获得 / 消耗」是复述画面已经发生的事，反应正文在日志里逐字可查。
> 这些文字仍**记进 `SYS_LOGS` 因果追踪**（`log(...)`），信息不丢，只是不再用浮层打扰。
> 唯一的即时反馈是 `LOCK` 密码窗输入错误时的**窗口抖动**（+ 一行日志）。

> 叙事卡被关掉后正文不会失联：单击场景节点 → 详情窗底部「[ 重看场景叙事 ]」重新放映。
> 日志里**不再单记一条**（放映是过程，不是结果）；要回溯就直接看这条正文本身。

## 数据里本来就有这套机制

原作的合成逻辑**已经写在案件数据里**，v2 只是把它图形化了：

```jsonc
// 目标.presentReactions[工具Id]  —— 拖「工具」到「目标」身上
"ITEMS_bd": {                          // 绷带
  "presentReactions": {
    "ITEMS_jd": {                      // 剪刀
      "text": "剪刀一点点剪开缠绕整具尸体的绷带……",
      "results": { "scene": "SCENES_lhsdst" }   // → 陆珩松的尸体
    }
  }
}

// 角色同理：char.itemReactions[工具Id] / char.reactions[工具Id]
"CHARS_zs": { "itemReactions": { "ITEMS_rxbs": { "text": "是我……将这把匕首插进了陆老师的腹部……" } } }
```

查找顺序：目标有反应表 → 反向（工具自己有反应表）→ 目标的 `useItem` 命令正好需要这个工具（如 黑胶 → 唱机）→ 目标（或工具）是**容器**（场景或书桌 / 垃圾桶这类容器物品）时，扫描它收着的物品/角色。拖到**场景**上松手另有一条「前往」分支：拖来的容器（场景或容器物品）文本里列着这个场景就算通路 —— 书桌正文里的「返回 `[loc:SCENES_garden]`」正是靠这条把书桌与花园连起来。
**同一个 id 只查一次，命中就打住**；没命中的组合会画成灰色虚线留在图上，避免无脑穷举。

### 素材（图片 / 字体 / 音频）—— 双构建

base64 不该出现在源码里：一行几千字符的乱码既看不出画的是什么，也没法替换或 diff。而「全内联单文件」与「外链可缓存」是两种发布场景，`build.js` 用**同一份源码**各出一份产物：

- **external 模式** → `index.html` / `_template.html`：占位符换成 `assets/<文件名>`，HTML 轻、浏览器按文件缓存、音频可流式可拖进度；构建时把 `src/assets/*` 复制到根目录 `assets/`（构建产物，.gitignore 忽略）。
- **inline 模式** → `tecnode-standalone.html` / `editor.html`：占位符换成 `data:<mime>;base64,<正文>`（mime 由 build.js 按扩展名推导，MIME 表在 build.js 顶部），单文件自包含、双击即玩。

于是二进制素材放 `src/assets/`（**入库**），源码只写占位符 —— 占位符本身就代表一个**完整可用的 src**，源码不感知模式差异：

```js
/* src/js/11-dialog.js —— 源码里看得懂 */
const TEC_AVATAR = "@@ASSET:tec-avatar.png@@";

/* src/js/16-cases.js —— 音乐也是普通素材 */
{ id: "Air_Bach", title: "Air (Bach)", src: "@@ASSET:Air_Bach.ogg@@" }
```

```css
/* src/css/01-font.css —— 占位符直接进 url() */
src:url(@@ASSET:font.ttf@@) format("truetype");
```

规则：external 时 `@@ASSET:<文件名>@@` → `assets/<文件名>`；inline 时 → `data:<mime>;base64,<正文>`。文件名允许带子目录（`flower/plant_seed.png` → `assets/flower/plant_seed.png`，`copyAssets` 递归镜像并清掉源目录已不存在的历史残留），但**严禁 `..` 上跳**。构建时会校验：素材名只允许字母数字与 `._-`（子目录段同规则）、文件必须存在、inline 模式下扩展名必须在 MIME 表里登记过、替换后不得有残留占位符，任一不满足就报错退出。

| 文件 | 用途 | 引用处 |
|---|---|---|
| `tec-avatar.png` | TEC 助手头像（右下角卡片 / 对话窗） | `src/js/11-dialog.js` |
| `executor-avatar.png` | 推演器中央「执行者」头像 | `src/js/13-matrix.js` |
| `emote-heartbroken.png` | 配方不匹配时的心碎表情 | `src/js/13-matrix.js` |
| `cert-avatar.png` | 调查员证上的**兜底**照片（选了头像就不用它；老存档 / 未选时用它） | `src/js/16-cases.js` |
| `Air_Bach.ogg` | 唱机装上唱针后可播放的内置音乐（Bach《Air》，弦乐） | `src/js/16-cases.js` |
| `font.ttf` | 凤凰点阵体 Vonwaon Bitmap 12px（CC0 1.0，已子集化） | `src/css/01-font.css` |

> **字体的格式标签为什么是 `truetype`**：这份点阵字体的字节实际是 sfnt/TTF（文件头 `00010000`，表含 `glyf`/`loca`/`maxp`），而不是 woff2。早期版本把它写成 `data:font/woff2` / `format("woff2")`，2026-10-14 改正为 `data:font/ttf` / `format("truetype")`。
>
> 改正前实测过影响面：Chromium 并不采信这两个标签，而是按字节内容嗅探真实格式 —— 把数据以 `text/plain` 提供、标签写 `woff2` 也照样加载成功，控制台零告警。所以这次改动**纯粹是消除标签与内容的自相矛盾**（避免后来者按 woff2 工具链去处理一个真·TTF），功能上零差异。唯一的副作用是产物字节不再与拆分前完全一致（见上文「构建」一节的说明），所以 `verify.js` 里没有、也不该有与字体字节挂钩的断言。

### 新增一个案件

1. **加数据文件**：把新案的 JSON 写进 `data/`（结构与 `case-a001.json` 同构）。
2. **在 `build.js` 里登记**：目前 `build.js` 只认 A-001（读 `data/case-a001.json` → 注入内联 `<script type="application/json" id="gamedata">`）。接第二个案件时，把它那一段提取成一张「案件表」（id → 数据文件），并为每案注入各自的 `<script type="application/json" id="gamedata-<id>">`；`src/shell.html` 里相应加占位符。
3. **注册进引擎**：在 `src/js/16-cases.js` 里把 `const CASE_DATA = { A001: DATA };` 扩成 `{ A001: DATA, A002: <该案数据> }`（数据对象来自上一步注入的那段 `<script>`）。
4. **案件库里加条目**：同文件的 `CASES` 数组补 `{ id, code, title, note }`。`title` 只是未解锁时的占位名；真正的案名写在案件 JSON 的 `config.caseTitle` 里。
5. **案件专属配置**（可选，写在该案 JSON 的 `config` 里）：`caseTitle` / `caseNote`（地图与标题栏）、`reusableTools`（永不消耗的道具）、`lightSources`（可点亮的光源）、`memoryScenes`（首次展开放 MEMORY 放映卡的场景 —— **同时是画布上「时间节点」的唯一判据**：列在这里的场景 id，节点 kind 是 `"time"` 而不是 `"loc"`）。不写就退回 A-001 的默认值。

最后 `node build.js && node verify.js`。

## 已知取舍

- **消耗规则是我定的默认值**：数据里没写「用完之后道具是否消失」。默认双方消耗，`REUSABLE_TOOLS`（手电筒 / 黄铜钥匙 / 唱机）永不消耗；与角色对话不消耗。权威清单写在案件数据的 `config.reusableTools` 里，引擎里那份只是"案件没写"时的兜底，两处保持一致。左上开关可整体关闭。如果原作语义不同，改一个数组即可。
- **唱针不在可复用清单里 —— 它"装上就没了"**：唱机有一条 `installs: true` 的 `useItem` 命令（「装上唱针」），成功时把唱针记进唱机的 `n.installed` 并**消耗掉唱针节点**。于是「放黑胶」那条命令可以写 `requires: ["ITEMS_cz"]` —— 没装唱针就放不出声。两个字段都是最小的数据词汇，走的是既有的开关灯标记（`n.lit`）同一条路：状态记在节点上、进快照、跟着撤销 / 续档走（`snapshot()` 的白名单里加了 `installed`）。旧档没有这个键 → 当空对象读，不会炸，只是"没装过"。
- **顶栏那个「自动布局」按钮已删除**（2026-10-14）。它看着像"整理画布"，实际只是把 `layout()` 在当前位置上再跑 260 轮弹簧迭代 —— 因为 `seed()` 对已有坐标的节点直接 `return`，所以既不重新播种、也远不到收敛。真机实测（`_cdp_relayout.cjs`）：开局点一次，**31/31 个节点全部移动，最大 165px、平均 54px**；再点一次又是 31/31 全动。玩家能看见的实际效果只有"我摆好的位置被抖散了 + 钉住全没了"。位置保护本来就有右键钉住这一条路，所以这个按钮连同它的副作用（批量解除「已固定」）一起删掉，不另立替代品。
- **场景节点上的「条件进入」角标已删除**（2026-10-14）。它挂在「未探索 + 没有任何文本入边 + 在 `condRoutes` 里」的场景节点上，而它想说的那件事别处也说得清楚（可达性检查里有「需条件触发才能进 5 个」），同一排还挤着「新 / 对话 N」。**它不是死代码**：组合「剪刀 ⇒ 绷带」开出的「陆珩松的尸体」走的是 `attemptCombo` 的 `results.scene` 分支，那条分支只 `ensureNode`、**不 `revealScene`**，所以开出来的场景是未探索的，正好撞上角标条件（选项那条路会顺手 `revealScene`，抽屉开出来的场景是已探索的，撞不上）。改前改后各跑一遍同一套真手势动作取过证（`_cdp_condbadge.cjs` 的 `CB_FILE` + `CB_TAG=before`）：改前该节点角标是 `[badge cond|条件进入, badge new|新]`，改后只剩 `[badge new|新]`。`condRoutes` 本身保留（可达性检查还在用它），节点上只剩「真的没路走」这一种警告 —— 而**警告分支必须带上 `!condRoutes[n.id]`**（旧代码靠 `else-if` 达到同一效果），否则撤掉一枚角标的当天就会在同一位置冒出另一枚。顺带把那个被复用的类名从 `.badge.cond` 改成 `.badge.cnt`：它其实一直是「实心药丸」这个通用样式，用在证物袋件数 / 线索册条数 / 推演器条数 / 日志未读 / 案件地图「已关闭」上，与"条件"毫无关系（`cond` 这个名字是历史误会）。
- **拖动中途 `render()` 会留下「幽灵节点」，必须先收尾再重建**：`render()` 无条件 `nodeLayer.innerHTML = ""` 重建全部节点 DOM，而节点拖动的收尾（`pointerup` / `pointercancel`）挂在**被拖的那个元素自己**身上 —— 元素一离树，指针捕获被隐式释放，收尾事件再也不会来，`#drag-layer` 里的镜像就永久留在画布上（表现为"拖动卡住 + 画布上多出一个点不动的节点"，刷新才消）。真实触发路径不是假想：**TEC 分析是 `setTimeout`**，玩家一边拖节点一边等分析，分析完成且**本次真产出新线索**时 `settle()` → `render()` —— 正是"拖着拖着线索掉下来"那一刻（`11-dialog.js`）；拖动中途点「撤销」同理会踩到。修法见 `07-render.js` 的**拖动收尾登记表**：`dragAborters` + `abortActiveDrags()`（render 前统一收尾：把位移写回 `n.x/n.y`、摘掉镜像与幽灵线、清落点高亮）+ `clearDragLayer()` 兜底；节点 / 种子 / 芯片 / 册行四种拖动各自 `registerDrag(abortXxx)`，收尾时 `unregisterDrag`。收尾**只写位置、不做落点判定** —— 此刻落点（组合对象 / 收纳窗）可能已被重建，按旧引用判了也是错的。
- **节点拖动在无头 CDP 里只能走合成 PointerEvent**：Chrome 的 `Input.dispatchMouseEvent` 在无头模式下**不做指针捕获重定向** —— 实测 `el.hasPointerCapture(1)` 已经是 `true`，但随后的 `pointermove` 仍被投给光标下的元素（也就是目标节点），源节点收不到 move、`moved` 永远是 false，节点拖不动（`_cdp_dragprobe.cjs` 的逐步取证）。真实浏览器里指针捕获照常生效，所以这是测试环境的限制、不是产品问题；项目里的真机脚本因此把"跨元素"的手势（节点拖动）用合成 `PointerEvent` 驱动，真鼠标只留给"点 / 右键"这类不跨元素的手势。
- **台灯的点亮是纯视觉状态**（节点上的 `lit` 标记 + 画布光晕），不进历史以外的任何游戏逻辑：可随撤销回退，重置后清除。
- **密码窗弹出时锚定在节点下方的世界坐标上**，画布平移 / 缩放时跟着节点走；它也是系统窗口，整窗可拖动挪到任意位置（拖动节点本身时窗口不跟手，× 关闭）。
- **对话队列 = 默认队列（talkQueue / defaultTalks / lines）+ 角色来源场景的 sceneTalks 拼接**，逐句推进、可撤销；队列耗尽后重复最后一句，进度不再增长。
- **叙事卡只在场景首次展开时出现**（适性测试结束后**不会**自动弹卡；起始场景也要玩家自己双击展开）；撤销回到未探索状态后再展开会重播。叙事卡是锚定在世界坐标上的临时浮层，**拖动节点时不跟随**，用右上角 × 关闭（点空白不会收起）；叙事文本不沉淀为持久节点，**正文只活在卡里**——日志也不再为放映单记一条（放映是过程，不是结果），卡片关掉后用详情窗的「[ 重看场景叙事 ]」重新放映。**正文以打字机逐字浮现**（`typeInto()`，约 45ms/字；先按全文实测并 `min-height` 预占整卡高度，所以打字期间卡片不塌缩、位置不跳，只是字逐个"长"出来）。
- **框体描边统一**：`.narr-card` 与 `#toast` 原本各带一条 `border-left:4px solid var(--line)` 的**左侧加粗色带**，已删除 —— 两者现在都是 `border:1px solid var(--edge)` 的整圈描边，与 `.detail-win / .bag-win / .goto-win / .infer-win / .map-win / .tec-win` 完全一致。（记忆放映卡 `.memory` 的「做旧双线框 + 深色标题栏」是**刻意的独立风格**，不在这次统一范围内。）
- **详情窗内不放内层方框**：曾经给物品加过一块内嵌的「结果 / 未成功」区块（圆角 + 边框 + 内影），叠在详情窗自己的圆角框里，观感是"框套框"。现在**窗内不再有任何内层框**：信息行只靠留白分行（`#detail-body .drow` 不再有 `border-top` 虚线），窗内的按钮（`#dt-renarr`「[ 重看场景叙事 ]」）降级成**无边框 / 无底 / 无阴影的纯文字链接**。整个面板只剩外层窗口一层框。
- **TEC 不是画布节点，而是桌面上的 ◉ 图标（屏幕坐标，不随画布平移缩放）**。提示上下文 = 最近展开的场景（`lastScene`）：该场景的 `sceneTalks` 逐句给完后，继续交谈轮换 `defaultTalks`；场景提示可撤销，默认轮换不进历史。拖节点到图标（或窗内头像）上 = **`tecAnalyze(key)` 延迟分析**：开窗 → 窗内插入「分析中 · 标签」进度条（动画时长 = 5000~8000ms）→ 完成后先 `tecReaction` 给评述；有未捕获的隐藏线索就落成画布上的 `clue:` 节点并计入 `G.captured`，没有则提示「没有可以捕获的线索」。线索节点拒绝再次分析，分析中（`tecBusy`）也拒绝。对话历史（`tecHistory`）是页面会话级的，不进快照。**TEC 窗是常驻助手窗**：只有「换案」与「重置」会关它 / 清历史，「– 收起 → 展开」回访同一案时窗口与对话都保留；`.tec-win` z-index 28，永远不被其它浮窗覆盖。**标题栏多了一个「– 最小化」**（`makeWindow(title, onClose, onMin)` 的第三参，只有传了才有）：
- **TEC「– 收起」= 收进右下角一块带头像的助手卡片 `#tec-chip`，进度画成卡片上的进度条**：`minTecWin()` 把窗口从屏幕上摘掉（`tecWinEl = null`）但置 `tecMin = true`（应用驻留）；`tecTask = { key, label, ms, endAt }` 记着分析任务与截止时刻，所以收起 / 还原之间能按**剩余时间**接着播同一根进度（`tecTaskLeft()` = 剩余毫秒，下限 400ms）。卡片结构：`.tc-av`（32px 圆角框 + 内嵌 base64 头像）+ 文案列 `.tc-name` / `.tc-status` / `.tc-bar`。`updateTecChip()` 在 `tecTask` 存在时给卡片加 `.busy`（`#tec-chip.busy .tc-bar{opacity:1}` 才让进度条显形），并**只在这一轮任务的第一次刷新时起播**（key = `key@endAt`；`updateTecChip` 会被 `render()` 反复调用，每次都重启动画会把进度条永远钉在 0%）。分析完成且窗口不在屏幕上时置 `tecDot = true`，`updateTecChip()` append 一个 `.tc-dot`（卡片右上角，`box-shadow` 描一圈亮色光晕），**打开 TEC 窗口即清除**（`openTecWin()`）。`tecAnalyze` 拆成 `tecAnalyzeStart` / `tecAnalyzeFinish`（`tecAnalyze` 只是「起任务 + 排定时器」的薄壳），这样收起态也能用 `window.__analyzeStart` / `__analyzeFinish` 观察「分析中」这一态。
- **进度条重启动画只能用 `animationName` 长写、CSS 也不能用 `animation` 简写**：`animation = "none"` 是**简写**，会把 inline 的 `animation-duration` 一起清零 → 动画退化成 0s、进度条瞬间跑满（真机实测踩到；DOM stub 的 `style` 是普通对象、不展开简写，所以 `verify.js` 查不出来，只有真机 `getComputedStyle` 才现形）。所以 restart 走 `fill.style.animationName = "none"` → 强制回流 → `= ""`，`animationDuration` 全程留在 inline；`#tec-chip .tc-bar i` 的 CSS 也从 `animation:tecana linear forwards` 改成 `animation-name / animation-duration / animation-timing-function / animation-fill-mode` 四条长写，顺便留 1s 兜底时长。**卡片靠 `bottom:84px` 排在案件卡片（`bottom:14px`）上方，两张卡片纵向不叠**（实测 14px 间距）。
- **收起态卡片可拖入，但清单要按状态门控**：拖节点的落点清单由 `nodeDropTargets()` 统一给出 —— 卡片即使熄着也**保留布局盒**（`visibility:hidden`），所以不能无条件把它当靶子，否则窗口开着时拖节点划过卡片所在位置会被误判成“拖到了 TEC”。只有 `tecChipOn`（收起态）才把 `"tec-chip"` 加进清单；悬停高亮与松手判决共用这一份清单，不会两边走岔。
- **`–` 最小化键也必须进 `makeFloatDraggable` 的排除表**：TEC 窗是整窗拖动（`h = el`），不排除的话 `setPointerCapture` 会把 `click` 重定向到窗口自己，`–` 永远点不动 —— 和 `.map-card` / `.goto-item` 是同一个坑，而合成 click 与 DOM stub 都测不出来（真机 CDP 才复现）。
- **TEC 对话窗的「点框内任意位置」必须把监听挂在窗口根 `w.el` 上，不能挂在正文 `.syswin-body` 上**：`makeFloatDraggable` 在 `pointerdown` 里对窗口根做了 `setPointerCapture()`，随后的 `click` 会被**重定向到窗口根**，事件路径**不再经过子节点**，挂在正文上的话点「历史行 / 提示行」一律不触发（只有助手头像例外 —— 它在拖动排除表里，起手时提前 return、没设捕获，`click` 才照常从它冒泡上来）。这类"合成分派"用 `dispatchEvent('click')` 甚至 DOM stub 都测不出，只有真机 `Input.dispatchMouseEvent` 才现形（`_cdp_tecadvance.cjs`）。标题栏的 `–` / `×` 各自 `stopPropagation`，不会误触发交谈。
- **`_dragged` 的复位必须放在拖动排除表之前**：`makeFloatDraggable` 的 `pointerdown` 里，从被排除的子元素（TEC 头像 / 清单项 / × 关窗键）上起手时会提前 `return`；若把「本次手势拖过没」的复位写在 `return` 之后，`_dragged` 会一直留着上一次拖窗口的 `true`，那些元素自己的"点击"就被误吞（表现为：**拖过 TEC 窗之后再点头像就不说话了**）。真机才有 —— DOM stub 的 `closest()` 恒返回 `null`，排除表在 stub 里等于不存在。
- **证物袋窗口排在落点清单最前 —— `nodeDropTargets()` 的顺序就是命中优先级**：`.bag-win` 的 `z-index:25` 高于图标层 `#icons` 的 `24`，窗口开着时**在视觉上盖住**左侧图标栏；而命中判决是纯 `getBoundingClientRect()`、**不感知 z 序**，所以必须把窗口放在最前，否则拖物品到窗口上会落进底下那张**看不见的**图标（推演器 / 档案）。代价：被窗口盖住的那几个图标在窗口开着时点不到 —— 窗口本身可拖动，属可接受的取舍。**实测影响很小**：窗口很矮（空袋 80px、装 1 件 71px，`body` 上限 300px），1280×820 下只与 `map-icon` 重叠，而地图图标不是落点。
- **桌面图标位置不进撤销栈，重置不回位**（刷新页面才恢复左侧竖排的默认站位）；节点拖放的落点命中顺序固定为 `bag-win`（开着时）> bag > tec > infer > goto，保证多个落点矩形重叠时行为确定；桌布 chip 拖出时则是「线索册（窗 / 图标）> 取回画布」。
- **桌面图标的「变黑」按下态不做过渡**：`background` 是 `linear-gradient`，加过渡既慢（120~140ms）又会途经过灰色，正是"点下去有滞后/不流畅"的来源；现在只有 `box-shadow / transform` 过渡，按下（`:active`）、选中（`.sel`）、拖过（`.over`）三种变黑都即时生效。
- **回弹 / 夹回时的连线同步**：`.node` 带 `left/top .34s` 过渡，所以"只写一次 `left/top` 再画一次线"必然脱线——线瞬间跳到终点、节点还在慢慢滑（实测最大脱开 108px）。凡是**由 JS 决定落点**的位移，一律走 `springBack(el, ox, oy)`：`transition:none` 接管后用 `setTimeout` 逐帧同时推进「节点位置 + `paintEdges()`」，结束再还原过渡。拖到画布**框边之外**松手时，世界坐标会被夹回 `[60,1780]×[50,1180]`，这条夹回路径同样走 `springBack`；未越界则原地落定，DOM 与模型（`n.x/n.y`）必须严格一致。`paintEdgesFor(ms)`（40ms 轮询）只用于 `render()` 的兜底跟随，**不能**用来兜弹回。
- **调查员信息存 localStorage（key `tec_investigator`）**：不可用 localStorage 的环境（如无头验证 stub）自动退化为内存态——当次会话有效，刷新后重新测试。重置案件（`btn-reset`）不会清除调查员身份；只有证件回看窗口里的「重新测试」会清档重来。
- **详情 / 日志是静态外壳的系统窗口**（`#detail-body` / `#log` 元素 id 与内容结构不变，选择器与日志捕获照常工作），可见性由引擎内布尔维护（无头环境兼容）。**详情检查器没有独立图标**：生命周期绑定选中态（选中即开、取消即关，× = 取消选中），重置时收回关闭；日志窗关闭期间的新日志在 ≡ 图标上计数。
- **详情面板的正文由 `paintDetail()` 统一渲染，`render()` 末尾会调它一次**：所以「状态」行（物品点亮 / 线索捕获 / 场景展开 / 角色对话进度）永远是当前值 —— 旧版只在 `selectNode` 那一刻渲染一次，于是点亮台灯后详情窗还写着「未点亮」。**面板内容只有三种：简介（`.ddesc`）/ 状态（`.drow`）/ 来源（`.drow`）**——见上面「DETAIL 详情窗」那张表；这个收口是**有意的**：不列结构关系（容器内容 / 文本入口 / 出口 / 反应清单），因为那都是玩家该自己动手试出来的东西。「状态」里的**使用条件**是唯一例外（防瞎试的前馈，只说「要什么」不说「跟谁配」）。面板内部按**内容签名**比对（`detailBody.__sig`）：与上一次逐字相同就直接跳过、不重建 DOM，避免无谓地打断 hover、把滚动位置弹回顶部。`selectNode` 只负责选中态（`.sel` / `sel` / 开窗）与首次绘制；清空选中 / 重置走 `detailPlaceholder()`（同时把签名对上，防止下一次误判"内容没变"）。
- **场景折叠按 `homeScene` 归属 + 边连通性做 fixpoint 收敛**：归属该场景且没有边连到"会保持可见"节点的内容物才被隐藏；**钉住（pinned）的节点不参与折叠**，线索节点不记 homeScene、永不隐藏。折叠状态进历史，可撤销。**折叠时若还有内容物留在画布上**（钉住的、或跨场景连着场外节点的），`toggleCollapse` 会在日志里补一句 `「X」另有 N 个节点留在画布上（已固定 / 与场外相连）`——玩家知道为什么"有的收得回、有的收不回"，不再误判成 bug。

  - 摘角标挂在节点自己的点击路径（`pointerup` 无位移分支 + `dblclick`），**不在 `selectNode` 里**：从线索册 / 人物名册**点清单行**也会 `selectNode`，那不是"点节点"，取回来的线索该照常亮一次「新」；且只在角标**已经画在屏上**才动手（`n.el` 为空说明还没重绘出来，留着让 `render()` 正常画）。
  - `unread` **不进快照**，但 `restore()` 会把它接力带回新图（和 `seenTexts` 一样属于玩家知识）—— 否则撤销 / 续档又会把角标洗一遍。代价：撤销可能把已经点掉的角标变回来（快照是那一刻的状态），比"全被洗掉"轻得多。
- **叙事卡锚定节点上方**：场景首次展开的 `SCENE_FEED` 叙事卡与记忆场景的 `MEMORY` 放映卡，统一通过 `anchorAboveOrBelow(c, n, 14)` 定位——先完成 `fit()` / `ensureVisible()` 定镜头，再按当前视图钳制，优先放在节点上方（卡底与节点顶留 14px 世界坐标间距）；若上方被视图上沿裁掉（节点太靠顶）则退到节点下方，**保证不盖住节点**。
- **案件地图与元进度**：`CASES` 是案件注册表，`CASE_DATA` 是案件数据注册表；解锁进度存 localStorage `tec_progress`（`unlocked` / `completed` / `last`），**与案件存档 `tec_case_<id>`、`tec_investigator` 相互独立**，重置案件不会清除解锁。解锁条件单一：`triggerEnding` 里只有 `ending.isTrueCapture`（真结局）才 `unlockNextCase`。**当前只内嵌 A-001 数据** —— 打完 A-001 真结局后 A-002 会解锁，但地图上显示「待接入」（地址已解锁 · 案件数据待装载），点击只提示"数据尚未装载"。**切案机制（形态 B：案件 = 默认最大化的窗口，外壳固定）已经完成并通过验证**，只等 A-002 的数据接进来。
- **切案过场的实现方式**：案件窗的淡出/淡入是 CSS `transition` + `setTimeout(180ms)`；无头验证器里 `setTimeout` 是空实现（返回 `0`），代码据此**同步换档**，所以测试不需要等定时器、也不会卡住。换档本身是同步的，动画只是装饰。
- **「点亮标记」是持久的，不是一次性闪动**：`lastEnteredCase` 记着上次进入的案件 id，回访地图时那一行带红框。因为地图窗口在换档时就关掉了，做一次性闪动没有意义。
- **案件窗离屏 ≠ 什么都没了**：`CASE_ID` 与 `CASE_DATA[CASE_ID]` 仍然加载着，只是窗口 `display:none`。所以离屏后顶栏那几个画布按钮如果不拦，就会去操作一个看不见的画布（尤其「重置」会调 `boot()` 把案件窗又弹回来），所以统一用 `requireCase()` 拦下并给提示。离屏时 `#stage` 尺寸为 0，任何依赖它尺寸的计算（`fit()`、`ensureVisible`）都会退化 —— 好在那时没有入口能触发它们。
- **注意 `</div>` 的位置**：`#stage` 里嵌着 `#world` 和 `#hint`，`#case-win` 里只嵌 `#stage`，`#icons` / `#log-win` / `#detail-win` 都在 `#case-win` **外面**。改这块 HTML 时务必让 div 配平 —— 少写一个 `</div>` 会让后面的元素被浏览器吞进案件窗里，**画布照常能玩、力导向照常跑，但桌面左栏会空掉**（图标其实跑到案件窗内侧去了），而且 DOM stub 的断言完全看不出来。`verify.js` 第 26 节就是为这个补的静态结构检查。
- **图标栏从桌面顶部起排（`top:16px`）**：图标在案件窗之外的独立栏里，占位简洁，所以不必像早期那样从 `top:180px` 让位。间距常规 85px，桌面高度不够时压到 `max(70, floor((H-28)/n))`。
- **整台 OS 外壳 `user-select:none`（输入框放行）**：以前只给 `.syswin-bar` 标题栏禁了选中，窗口**主体**没有 —— 而浮窗是**整窗可拖**（`h = el`），所以按住正文里的文字一挪就变成「拖选文字」，整段被蓝色高亮盖住。现在 `body{user-select:none;-webkit-user-select:none}` 一把盖住，再用 `input,textarea,[contenteditable]{user-select:text}` 放行输入框。规则必须写在 `*{scrollbar-...}` 那条之后才盖得住；`-webkit-` 前缀两个属性都要写（`getComputedStyle` 认 `.userSelect`，部分内核只认前缀版）。
- **对话/放映是「点框内任意位置推进」，靠 `_dragged` 区分点击与拖动**：气泡与记忆放映卡都绑了 `click` 处理器 —— 打字中点击先 `cancelType` + 补全整句并 `return`（不推进），否则 `adv()` 走下一句。`makeFloatDraggable` 在 `pointerdown` 复位 `_dragged=false`、位移 > 5px 置真、`click` 里 `if (_dragged) return` —— 真机实测 Chrome 在拖动收尾**确实会补发一次 `click`**（在气泡上挂 click 计数器读到 1），没有这道闸门就会「拖一下顺手翻到下一句」。**注意语义**：`_dragged` 挡的是**同一次手势**拖尾的那下 click；玩家拖完**另起一次**的正常单击仍然照常推进（用户要的就是这个）。
- **打字机计时器记在元素自己身上（`el._twTimer`）**：原来用一个全局 `twTimer`，气泡 / 叙事卡 / 放映卡可以同时在场，后一个开打字会把前一个**掐断**（放映卡每行一个 `<div>`，症状最明显）。`cancelType(el)` 也改成按元素取消。记忆放映卡同时**去掉了 700ms 自动换行** —— 现在完全由点击驱动（`window.__playStep` 手动推进，供无头测试用）。
- **`makeFloatDraggable` 的拖动排除表必须带上行内可点的清单项**（`button,input,.bag-item,.map-card,.goto-item,.syswin-x,.syswin-min,.tec-avatar,.mx-exec,.mx-chip,.music-row,.gd-narr`）。**花园叙事框是第三次踩这个坑**（前两次：案件地图地址卡、TEC 头像）：它是「整框点一下 = 看下一段」，但花园窗是整窗可拖的 —— 按下叙事框时窗口 `setPointerCapture()`，`pointerup` 与 `click` 双双被改派到窗根，叙事框自己的 `click` 永远收不到（用户报的「点花魄的叙事文本没有继续」）。真机事件流取证：`pointerdown → .gd-narr-p` / `pointerup → .syswin garden-win` / `click → .syswin garden-win`。浮窗拖动是在窗口元素上 `setPointerCapture()`，**指针按下时如果没被排除，后续 `click` 会被重定向到窗口自己，行内的 `.map-card` / `.goto-item` 永远收不到点击**。症状极具迷惑性：案件地图地址卡、档案条目点不动（「收进后无法再进入」就是这么来的），但合成 `dispatchEvent('click')` 照样能触发 —— **只有真机 `Input.dispatchMouseEvent` 才复现得出**。以后往浮窗里加可点行内元素，记得往这个 `closest()` 里补一个类名。
- **`#intro-backdrop` 是覆盖整屏的遮罩（`position:fixed; z-index:90`）**：开场适性测试没走完时，它会吞掉**所有**真实鼠标事件（`document.elementFromPoint` 返回的就是它）。做真机点击验证时必须先 `window.__intro.finish()`，否则会误判成"按钮点不动"。
- **离屏 / 展开动画走 JS 内联过渡，不用 CSS class**：`parkCase(p)` 里 `caseParkMotion(p)` 选落点（`caseDockMotion()` 量 `#case-dock`、`caseIconMotion()` 量 `#map-icon .icon-glyph`），用 `getBoundingClientRect()` 算出目标 `translate(dx,dy) scale(s)`（中心对齐、缩放取宽高的较小比值），`caseMotionApply()` 上过渡、`caseMotionPlayIn(p)` 反向播放；`caseMotionReset()` 收尾清掉内联样式，避免残留错位。因为要起点终点动态量取，写成 CSS 动画做不到。实测落点：右下角卡片 **948×463 → 170×56**、中心 (574,298) → (963,503)。**只有 `–` 收起（dock）走这套收缩动画**（`const m = (p === "dock") ? caseParkMotion(p) : null;`）；**`×` 关闭（icon）不做动画、直接 `finish()` 离屏**（用户反馈「缩进图标」那下不舒服），但**展开回来时两个落点都仍走 `caseMotionPlayIn(p)`**。
- **卡片只用 `visibility:hidden` 隐藏、不用 `display:none`**：保留布局盒，这样它作为落点时**随时量得到 `getBoundingClientRect()`**（`caseMotionPlayIn` 要在卡片熄掉之后还能量到它的位置）。`display:none` 会量出 0×0，动画直接退化成瞬移。
- **卡片拖动必须吞掉"拖完紧跟的那一次 click"**：`attachDock` 用 `moved` 标记（`pointerdown` 复位、位移 > 5px 置真、`click` 里 `if (!moved) enterCase(...)`），否则按住把卡片拖走会顺手把案件展开。**别用 `setTimeout` 复位 `moved`** —— 无头 stub 里 `setTimeout = () => 0`，回调永不执行会**永久吞掉后续点击**。卡片拖动后不复位（切案也保留玩家摆的位置），`z-index:23` 高于浮窗。
- **两个落点靠 `caseParkedAt()` 消歧**：`caseOpen ? null : (caseDockOn ? "dock" : (caseHeld ? "icon" : null))`。`enterCase` 从它返回的地方放大展开；`doEnterCase` 进新案时会把两个落点一起清掉，保证互斥。
- **「案件地图」图标被拖走后，切案 / 重置会被 `resetIconPositions()` 拉回左侧竖排原位**（它就在 `ICON_LAYOUT` 里）。所以"有关闭的案件"只体现在角标上、不体现在位置上；关闭动画也总是飞向图标的当前位置（而不是某个写死的坐标）。
- **字体：凤凰点阵体 Vonwaon Bitmap 12px**（作者 Haoyu Qiu，CC0 1.0）。按 `index.html` 中实际出现的 1406 个字符子集化，输出 sfnt/TTF（源文件 257 KB，见 `src/assets/font.ttf`）：standalone 内联为 base64 `@font-face`，index 成品走 `assets/font.ttf` 外链，`body` 的 `font-family` 以 `"VonwaonBitmap"` 为首，保留 `"SimSun","NSimSun","MS Mincho","MS Gothic",serif` 作为兜底，用于用户输入名或子集未覆盖的字符。字体是矢量轮廓但绘制成像素块，因此在 12px 整数倍时最锐利，其它字号仍保持可读。由于该字体只有单权重，`@font-face` 声明覆盖 `100–900` 并配合 `body{ font-synthesis:none }`，避免浏览器对 `font-weight:700` 的文字做伪粗（faux-bold）而导致发虚。

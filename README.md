# T.E.C-OS 节点原型 MVP v2

把 T.E.C-OS（案件 A-001）的交互从「命令行 + 超链接」改成 **Nodes 式节点图**：**拖拽 = 合成**。

单文件、零依赖、真实 A-001 数据内嵌。双击 `index.html` 就能玩。**没有改动 `chrisutada.github.io` 仓库里的任何文件。**

> 界面主题：复古单色系统风（灵感来自 PC-98 时代 OS / 早期 Windows 界面）——米白 + 墨色的单色世界，直角细黑框窗口、衬线 bitmap 字体；唯一的彩色是台灯点亮时的暖黄光晕。主题纯 CSS 实现，交互逻辑与类名钩子未动。
>
> **桌布 = 暖象牙纸**：三层叠加做纸感 —— 细颗粒（`feTurbulence` 噪波，`soft-light` 混合，均值中性不压暗底色）＋ 零星深色纸屑（阈值化噪波，`multiply`，覆盖率约 1.3%）＋ 大面积色斑（三个 radial-gradient 表现纸张不匀），最后一层极淡的边缘压暗。噪波以内联 SVG data-URI 内嵌，无外部图片依赖。调参入口集中在 `:root` 的 `--paper-grain` / `--paper-fleck` 与 `#stage` 的 `background-*` 一组声明里。

## v2 相对 v1 的改动（核心）

| | v1（错的方向） | v2 |
|---|---|---|
| 拖拽 | 移动节点位置 | **拖 A 到 B 上 = 组合使用** |
| 布局 | 手工自由摆放 | 力导向自动布局，节点不用摆 |
| 场景 | 双击「下钻」，独立页面 | 双击**展开**，里面的东西掉到画布上、永久留在图上 |
| 合成 | 无 | 有：产出新节点 / 新场景，并**消耗**参与节点 |
| 密码 / 选项 | 无 | 全在节点上：双击木盒弹密码框输 0321、双击抽屉弹出左/右抽屉节点 |

## 操作

|---|---|
| **拖动节点** | **移动位置**（跟手）。松手落在空白处就停在那，并**锁定**，之后自动布局不再挪它 |
| **拖到另一个节点上松手** | **组合**。命中则产出新节点/新场景并消耗参与节点；节点自己被弹回原位 |
| **拖到已折叠的场景节点上** | **把节点放回现场（收纳）**：节点存进该场景（保留连边），展开场景时取回 |

**多案件（每案一档 + 案件窗口化）**

**分层**：`#desktop`（桌面层）> `#case-win`（案件窗，只装 `#stage` 画布）+ `#icons` / `#case-dock`（收起后的案件卡片）/ `#log-win` / `#detail-win` / `#toast`（都是 `#case-win` 的**兄弟**，同挂在桌面层上）。桌面层左侧留出 100px 的**图标栏**，案件窗从 `left:100px` 起铺开。图标栏从桌面顶部（`top:16px`）开始竖排，间距 85px；桌面高度不够时自动压缩间距，保证最后一个图标不被 `#desktop{overflow:hidden}` 裁掉。第 6 个图标就是**「案件地图」**——它既开地图窗口，也接收被收起的案件（见下）。

- **一档一案**：离开一个案（切案 / 案件窗离屏）时，把当前案的 `G` 快照写进 localStorage `tec_case_<id>`（与撤销栈同一套序列化），回访时原样恢复 —— 节点位置、已捕获线索、逻辑阵列、结局记录全都各归各案。
- **案件窗离屏有两个落点，互斥**：都走同一个 `parkCase(p)`（先存盘 → 收缩动画 → 隐藏窗口 → 点亮落点），只是 `p` 不同 —— `stowCase()` = `parkCase("dock")`（标题栏 **`–` 收起**，落到右下角卡片 `#case-dock`），`closeCase()` = `parkCase("icon")`（标题栏 **`×` 关闭**，落到 `#map-icon .icon-glyph` 图标方块中心）。两者都先把进度（含镜头 `__view`）存进本案的档，**都不自动打开案件地图**。落点提示：卡片亮起 `.on` + 显示案号案名；图标打**「已关闭」角标**（`setCaseHeld(true)`，复用现有的 `.badge` 机制）。
- **要拿回来**：双击「案件地图」图标 → 地图窗口 → 点本案那行；或直接点右下角卡片。`caseParkedAt()` 记住它落在哪，`enterCase` 用 `caseMotionPlayIn(p)` 从那个落点放大展开，原位续档 —— 而不是重新 `fit()` 把整张图缩到最小。老存档没有 `__view` 就退回 `fit()`。
- **「案件地图」图标本来就可拖动**（它走通用的 `attachIcon`，和左侧其它图标同一套「单击选中 / 拖动换位 / 双击开窗」），所以"能拖"是白拿的；拖动时角标跟着走。
- **进入案件的三种情况**：已经开着本案 → 空操作；开着别的案 → 存旧案 + 换档；本来离屏 → 不存旧案，直接读档进入并从它上次落下的落点展开。
- **切案 / 案件窗离屏会清的**：撤销栈 `history`、TEC 对话历史 `tecHistory`、桌面图标位置。**不会清的**：解锁进度 `tec_progress`、顶栏的调查员证 `tec_investigator`。
- **「重置」只清当前案**：重置会连同本案存档 `tec_case_<id>` 一起删掉，别的案的档不受影响。
- **案件数据要自己报名字**：案件 JSON 的 `config` 里可写 `caseTitle`（地图与案件窗显示的案名）、`caseNote`（地图副标题）。`config` 里没写时退回 `CASES` 注册表里的占位名（A-002 现在是「？？？？？？」）。
- **地图行五档状态**：`加密`（未解锁）/ `进入`（本案，案件窗离屏）/ `当前`（本案，案件窗开着）/ `待接入`（已解锁但数据没装载）/ `可进入`（别的已解锁案）。`lastEnteredCase` 记着上次进入的案件，那一行带红框点亮。

| 记忆场景（6月2日 / 7月4日）首次展开 | **MEMORY 放映卡**：叙述 + 在场角色的场景台词逐行播放（做旧黑标题栏样式），可拖动、× 关闭 |
| 双击场景节点 | 展开该场景内的物品 / 角色 / 线索节点，永久留在画布；**首次展开弹出叙事卡片**（`SCENE_FEED` 系统窗口，归档进 SYS_LOGS）；**双击已展开的场景 = 折叠收纳**（内容物隐藏，被用到别处的节点会留下，再双击恢复） |
| 双击物品节点 | 执行它的主命令（打开 / 查看 / 使用）。**台灯 = 点亮 / 熄灭**（节点发光 + 画布光晕）；**抽屉 = 直接把「左侧抽屉」「右侧抽屉」弹成画布上的场景节点**；**木盒 = 弹出 `LOCK` 密码窗** |
| 双击角色节点 | **逐句对话**：`DIALOG` 系统窗口气泡（阅后即焚，归档进日志）；节点右上角紫色角标显示未读句数 |

> 所有浮窗（叙事卡 / 对话气泡 / TEC 对话窗 / 密码窗 / 各应用窗口）统一为**系统窗口样式**：标题栏（`SCENE_FEED //`、`DIALOG //`、`TEC //`、`LOCK //`、`STORAGE //`、`ARCHIVE //`、`INFERENCE //` 命名），**整个窗口都可拖动**（× 按钮和输入框除外），用右上角 **× 关闭**（点空白不会收起，方便对照文本继续探索）。

| 拖 黑胶 / 唱针 → 唱机 | 对应唱机的 `useItem` 命令（放入黑胶 / 播放音乐） |
| 双击线索节点 | 捕获线索 |
| 单击节点 | **选中并聚焦邻居 + 打开 `DETAIL // 节点详情` 检查器**：无关节点和连线被淡化（顶栏「聚焦选中」开关可关闭）；详情检查器选中即开、取消选中/点空白/× 即关。**它是信息表，不是第二个阅读器**：只放场景出入口、线索**感官类型**、物品**来源场景**、角色对话进度等结构信息，并提供「**[ 重看场景叙事 ]**」按钮把叙事卡叫回来。**同一段描述只在别处都看不到时才在这里出现**（如：有命令的物品、线索、角色）—— 详见下方「去重规则」 |
| 空白处拖动 / 滚轮 | 平移 / 缩放画布 |
| **自动布局 / 适应窗口 / 撤销 / 重置** | 清掉锁定重新排版 / 缩放到可见 / 回退一步 / 回到初始 |
| **合成消耗**（左上开关） | 关掉后道具不消失，方便反复试 |
| 检查可达性 | 报告有多少场景没有文本入口 |

> **移动与组合不抢同一个手势**：靠"松手的位置"区分 —— 落在空白处是移动，落在别的节点上是组合。
> 想重新排版，点「自动布局」即可清除所有手动位置。

## 去重规则（一段文本只在一个地方出现）

三个界面各管一类信息，互不逐字复读：

| 界面 | 职责 | 不再做的事 |
|---|---|---|
| 🗔 **SCENE_FEED 叙事卡** / 💬 提示条 | 承载**正文**（场景叙事、物品描述、对话台词） | — |
| ≡ **SYS_LOGS 日志** | 只记**一行事件**（谁对谁做了什么） | 不再镜像浮层全文 |
| ▤ **DETAIL 详情窗** | 只放**结构信息** | 不再复读别处已有的描述 |

判定规则很机械：**只在「这段文本别处已经看得到」时，才从详情窗移除** —— 去重，但不丢内容。

| 节点 | 描述文本的出口 | 详情窗 |
|---|---|---|
| 场景 | 叙事卡（正文唯一出口） | 不放正文，给「[ 重看场景叙事 ]」按钮 |
| 物品（**无**命令） | 双击 → 提示条 | 不放 |
| 物品（**有**命令） | 双击跑的是命令，描述没有别的出口 | **保留** |
| 线索 | 捕获后在详情窗可读，无其他出口 | **保留** |
| 角色 | 一句话身份，无其他出口 | **保留** |

> 叙事卡被关掉后正文不会失联：单击场景节点 → 详情窗底部「[ 重看场景叙事 ]」重新放映。
> 日志里对应的只有一行：`〔场景〕标题：叙事卡已放映`。

## 数据里本来就有这套机制

原作的合成逻辑**已经写在案件数据里**，v2 只是把它图形化了：

```jsonc
// 目标.presentReactions[工具Id]  —— 拖「工具」到「目标」身上
"ITEMS_bd": {                          // 绷带
  "presentReactions": {
    "ITEMS_jd": {                      // 剪刀
      "text": "剪刀一点点剪开缠绕整具尸体的绷带……",
      "results": { "scene": "SCENES_lhsdst" }   // → 陆珩松的尸体
    }
  }
}

// 角色同理：char.itemReactions[工具Id] / char.reactions[工具Id]
"CHARS_zs": { "itemReactions": { "ITEMS_rxbs": { "text": "是我……将这把匕首插进了陆老师的腹部……" } } }
```

查找顺序：目标有反应表 → 反向（工具自己有反应表）→ 目标的 `useItem` 命令正好需要这个工具（如 黑胶 → 唱机）→ 目标是场景时扫描场景内物品/角色。
**同一个 id 只查一次，命中就打住**；没命中的组合会画成灰色虚线留在图上，避免无脑穷举。

### 新增一个案件

1. **注入数据**：把 `_template.html` 里的占位符替换成案件 JSON，另存为该案的成品（或按下面的脚本生成 `index.html`）。
2. **注册进注册表**：在 `CASE_DATA` 里加一行 —— `const CASE_DATA = { A001: DATA };` 改成 `{ A001: DATA, A002: <该案数据> }`。数据可以内嵌（多一份 `<script type="application/json" id="gamedata-a002">`），也可以外部 JSON 拉取后 `CASE_DATA.A002 = json`。
3. **案件库里加条目**：`CASES` 数组补 `{ id, code, title, note }`。`title` 只是未解锁时的占位名；真正的案名请在案件 JSON 的 `config.caseTitle` 里写。
4. **案件专属配置**（可选，写在该案 JSON 的 `config` 里）：`caseTitle` / `caseNote`（地图与标题栏）、`reusableTools`（永不消耗的道具）、`lightSources`（可点亮的光源）、`memoryScenes`（首次展开要放 MEMORY 放映卡的场景）。不写就退回 A-001 的默认值。

```bash
python - <<'EOF'
import json, io
tpl  = io.open('_template.html', encoding='utf-8').read()
data = json.load(io.open('../chrisutada.github.io/data/game-a001.json', encoding='utf-8'))
payload = json.dumps(data, ensure_ascii=False, separators=(',', ':')).replace('</', '<\\/')
io.open('index.html', 'w', encoding='utf-8').write(tpl.replace('__GAME_DATA_A001__', payload))
EOF
```

## 已知取舍

- **消耗规则是我定的默认值**：数据里没写「用完之后道具是否消失」。默认双方消耗，`REUSABLE_TOOLS`（手电筒 / 黄铜钥匙 / 唱针 / 唱机）永不消耗；与角色对话不消耗。左上开关可整体关闭。如果原作语义不同，改一个数组即可。
- **台灯的点亮是纯视觉状态**（节点上的 `lit` 标记 + 画布光晕），不进历史以外的任何游戏逻辑：可随撤销回退，重置后清除。
- **密码窗弹出时锚定在节点下方的世界坐标上**，画布平移 / 缩放时跟着节点走；它也是系统窗口，整窗可拖动挪到任意位置（拖动节点本身时窗口不跟手，× 关闭）。
- **对话队列 = 默认队列（talkQueue / defaultTalks / lines）+ 角色来源场景的 sceneTalks 拼接**，逐句推进、可撤销；队列耗尽后重复最后一句，进度不再增长。
- **叙事卡只在场景首次展开时出现**（开局也会显示起始场景的入场叙述）；撤销回到未展开状态后再展开会重播。气泡与叙事卡都是锚定在世界坐标上的临时浮层，**拖动节点时不跟随**，用右上角 × 关闭（点空白不会收起）；叙事文本不沉淀为持久节点，**正文只活在卡里**——日志只留一行 `〔场景〕标题：叙事卡已放映`，卡片关掉后用详情窗的「[ 重看场景叙事 ]」重新放映。
- **TEC 不是画布节点，而是桌面上的 ◉ 图标（屏幕坐标，不随画布平移缩放）**。提示上下文 = 最近展开的场景（`lastScene`）：该场景的 `sceneTalks` 逐句给完后，继续交谈轮换 `defaultTalks`；场景提示可撤销，默认轮换不进历史。拖节点到图标上 = 查 `itemReactions`/`reactions` 给出分析，命中不消耗节点，未命中记入 tried 避免穷举；对话历史（`tecHistory`）是页面会话级的，不进快照。
- **桌面图标位置不进撤销栈，重置不回位**（刷新页面才恢复左侧竖排的默认站位）；节点拖放的图标命中固定优先级 bag > tec > infer > goto，保证多个图标矩形重叠时行为确定。
- **调查员信息存 localStorage（key `tec_investigator`）**：不可用 localStorage 的环境（如无头验证 stub）自动退化为内存态——当次会话有效，刷新后重新测试。重置案件（`btn-reset`）不会清除调查员身份；只有证件回看窗口里的「重新测试」会清档重来。
- **详情 / 日志是静态外壳的系统窗口**（`#detail-body` / `#log` 元素 id 与内容结构不变，选择器与日志捕获照常工作），可见性由引擎内布尔维护（无头环境兼容）。**详情检查器没有独立图标**：生命周期绑定选中态（选中即开、取消即关，× = 取消选中），重置时收回关闭；日志窗关闭期间的新日志在 ≡ 图标上计数。
- **场景折叠按 `homeScene` 归属 + 边连通性做 fixpoint 收敛**：归属该场景且没有边连到"会保持可见"节点的内容物才被隐藏；**手动摆过（pinned）的节点不参与折叠**，线索节点不记 homeScene、永不隐藏。折叠状态进历史，可撤销。
- **聚焦选中只是视觉淡化**（节点加 `dim`、非相关边降透明度），不影响任何交互逻辑；点空白即退出聚焦。所有浮窗（叙事卡 / 对话气泡 / TEC 对话窗 / 密码窗 / 应用窗口）统一为系统窗口样式：标题栏拖动、右上角 × 关闭；点空白不会收起浮窗。
- **收纳 ≠ 折叠**：折叠是视觉开关，收纳是玩家主动把节点移出画布存进场景（场景=现场仓库，画布=线索板）。收纳的节点**保留全部连边但暂不绘制**，取回后关系网原样恢复（不会留下悬挂的 tried 边）；收纳会把节点的归属场景更新为目标场景并解除钉住；单个拖放收纳允许 pinned 节点（玩家明确意图），批量收回跳过 pinned；场景节点（loc）不可被收纳。
- **证物袋与场景收纳共用同一套 stored 机制**（袋中节点 `storedIn === "BAG"`）：同样保留连边、可撤销、不计入可见数；`bagFrom` 记录来源场景用于清单标注。两者的取回路径不同——场景收纳在展开场景时批量取回，证物袋在清单里逐个点取。
- **「听说过」= 已展开 ∪ 在画布 ∪ 已见文本中的 `[loc:]` 标签或场景标题点名**：玩家见过的文本（合成/命令/密码/TEC 分析的成功与失败消息）都进 `seenTexts`（上限 200 条），**不随撤销丢失**（知识一旦获得不回退）；GOTO 窗口据此给出场景索引。捕获对无 hiddenClue 的节点记 `cap:` tried，防止无脑穷举。
- **逻辑阵列只记线索 id**，线索节点本身留在画布上（归槽不消耗）；槽位/结局状态进快照可撤销。结局演出是**步进状态机**（浏览器里 setTimeout 自动推进、点击立即跳过、无头测试用钩子手动推进），真结局未达成前名称显示为「真名捕获：？？？」。
- **记忆场景列表是 A-001 的硬编码常量**（`SCENE_MEMORY = 6月2日 / 7月4日`），换案件时需要更新。
- 力导向布局是自动的，但**手动拖过的节点会被锁定**（`n.pinned`），自动布局不再动它 —— 想统一重排点「自动布局」。
- 命中测试按「离光标最近」选目标，多节点重叠时不会选错。
- 条件跳转 `conditional` 需要线索已捕获才放行，捕获入口在双击线索节点。
- 起始场景直接是「植物学家的花园」：原作的 `startScene` 是「T.E.C-OS」引导场景，教学的是命令行玩法，在节点版里没有意义，因此跳过（它会成为可达性检查里的孤岛，属预期）。
- **展开自动居中（ensure-visible）**：双击**首次**展开场景时，仅当「场景节点 + 本次新内容」的包围盒**超出或贴边**视野，才以约 240ms 缓动平移镜头使其居中；已在视野内则**不动镜头**。只平移、**不改缩放**，玩家一拖动/滚轮即打断。顶栏「展开自动居中」开关可关；不作用于物品/角色/线索的双击，也不作用于折叠/再展开；视角不进撤销栈。
- **案件地图与元进度**：`CASES` 是案件注册表，`CASE_DATA` 是案件数据注册表；解锁进度存 localStorage `tec_progress`（`unlocked` / `completed` / `last`），**与案件存档 `tec_case_<id>`、`tec_investigator` 相互独立**，重置案件不会清除解锁。解锁条件单一：`triggerEnding` 里只有 `ending.isTrueCapture`（真结局）才 `unlockNextCase`。**当前只内嵌 A-001 数据** —— 打完 A-001 真结局后 A-002 会解锁，但地图上显示「待接入」（地址已解锁 · 案件数据待装载），点击只提示"数据尚未装载"。**切案机制（形态 B：案件 = 默认最大化的窗口，外壳固定）已经完成并通过验证**，只等 A-002 的数据接进来。
- **切案过场的实现方式**：案件窗的淡出/淡入是 CSS `transition` + `setTimeout(180ms)`；无头验证器里 `setTimeout` 是空实现（返回 `0`），代码据此**同步换档**，所以测试不需要等定时器、也不会卡住。换档本身是同步的，动画只是装饰。
- **「点亮标记」是持久的，不是一次性闪动**：`lastEnteredCase` 记着上次进入的案件 id，回访地图时那一行带红框。因为地图窗口在换档时就关掉了，做一次性闪动没有意义。
- **案件窗离屏 ≠ 什么都没了**：`CASE_ID` 与 `CASE_DATA[CASE_ID]` 仍然加载着，只是窗口 `display:none`。所以离屏后顶栏那几个画布按钮如果不拦，就会去操作一个看不见的画布（尤其「重置」会调 `boot()` 把案件窗又弹回来），所以统一用 `requireCase()` 拦下并给提示。离屏时 `#stage` 尺寸为 0，任何依赖它尺寸的计算（`fit()`、`ensureVisible`）都会退化 —— 好在那时没有入口能触发它们。
- **注意 `</div>` 的位置**：`#stage` 里嵌着 `#world` 和 `#hint`，`#case-win` 里只嵌 `#stage`，`#icons` / `#log-win` / `#detail-win` 都在 `#case-win` **外面**。改这块 HTML 时务必让 div 配平 —— 少写一个 `</div>` 会让后面的元素被浏览器吞进案件窗里，**画布照常能玩、自动布局照常跑，但桌面左栏会空掉**（图标其实跑到案件窗内侧去了），而且 DOM stub 的断言完全看不出来。`verify.js` 第 26 节就是为这个补的静态结构检查。
- **图标栏从桌面顶部起排（`top:16px`）**：图标在案件窗之外的独立栏里，不再和画布左上角的 `#hint` 重叠，所以不必像早期那样从 `top:180px` 让位。间距常规 85px，桌面高度不够时压到 `max(70, floor((H-28)/n))`。
- **`makeFloatDraggable` 的拖动排除表必须带上行内可点的清单项**（`button,input,.bag-item,.map-card,.goto-item,.syswin-x`）。浮窗拖动是在窗口元素上 `setPointerCapture()`，**指针按下时如果没被排除，后续 `click` 会被重定向到窗口自己，行内的 `.map-card` / `.goto-item` 永远收不到点击**。症状极具迷惑性：案件地图地址卡、档案条目点不动（「收进后无法再进入」就是这么来的），但合成 `dispatchEvent('click')` 照样能触发 —— **只有真机 `Input.dispatchMouseEvent` 才复现得出**。以后往浮窗里加可点行内元素，记得往这个 `closest()` 里补一个类名。
- **`#intro-backdrop` 是覆盖整屏的遮罩（`position:fixed; z-index:90`）**：开场适性测试没走完时，它会吞掉**所有**真实鼠标事件（`document.elementFromPoint` 返回的就是它）。做真机点击验证时必须先 `window.__intro.finish()`，否则会误判成"按钮点不动"。
- **离屏 / 展开动画走 JS 内联过渡，不用 CSS class**：`parkCase(p)` 里 `caseParkMotion(p)` 选落点（`caseDockMotion()` 量 `#case-dock`、`caseIconMotion()` 量 `#map-icon .icon-glyph`），用 `getBoundingClientRect()` 算出目标 `translate(dx,dy) scale(s)`（中心对齐、缩放取宽高的较小比值），`caseMotionApply()` 上过渡、`caseMotionPlayIn(p)` 反向播放；`caseMotionReset()` 收尾清掉内联样式，避免残留错位。因为要起点终点动态量取，写成 CSS 动画做不到。实测落点：右下角卡片 **948×463 → 170×56**、中心 (574,298) → (963,503)；「案件地图」图标 **948×463 → 47×23**、中心 → (50,475)（图标方块中心）。两个落点都**误差 0px**。
- **卡片只用 `visibility:hidden` 隐藏、不用 `display:none`**：保留布局盒，这样它作为落点时**随时量得到 `getBoundingClientRect()`**（`caseMotionPlayIn` 要在卡片熄掉之后还能量到它的位置）。`display:none` 会量出 0×0，动画直接退化成瞬移。
- **卡片拖动必须吞掉"拖完紧跟的那一次 click"**：`attachDock` 用 `moved` 标记（`pointerdown` 复位、位移 > 5px 置真、`click` 里 `if (!moved) enterCase(...)`），否则按住把卡片拖走会顺手把案件展开。**别用 `setTimeout` 复位 `moved`** —— 无头 stub 里 `setTimeout = () => 0`，回调永不执行会**永久吞掉后续点击**。卡片拖动后不复位（切案也保留玩家摆的位置），`z-index:23` 高于浮窗。
- **两个落点靠 `caseParkedAt()` 消歧**：`caseOpen ? null : (caseDockOn ? "dock" : (caseHeld ? "icon" : null))`。`enterCase` 从它返回的地方放大展开；`doEnterCase` 进新案时会把两个落点一起清掉，保证互斥。
- **「案件地图」图标被拖走后，切案 / 重置会被 `resetIconPositions()` 拉回左侧竖排原位**（它就在 `ICON_LAYOUT` 里）。所以"有关闭的案件"只体现在角标上、不体现在位置上；关闭动画也总是飞向图标的当前位置（而不是某个写死的坐标）。

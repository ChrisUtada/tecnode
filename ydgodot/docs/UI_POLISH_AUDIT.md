# UI 美化审计与修复清单

> 日期：2026-10-22  
> 范围：桌面图标、窗口标题栏控制、角标、页眉开关、一次性圆角与相关视觉细节。  
> 基准：Godot 当前 1x 原生渲染，对照 `docs/p3/web/start.png` 与 Web `index.html`。  
> 状态：**U1–U6 已实现，U7 已复核保留方角，U8 随 U2 修复；本轮已提交。** 全套无头测试现为 **1168 项 0 失败**；上一提交 `3ae7d60` 为 1154 项。
> 优先级：**P0 = 明显像坏了/影响可读性**；P1 = 一眼能看出的体系不一致；P2 = 细节收口；P3 = 设计取舍。

---

## 0. 一句话结论

当前最显眼的问题不是“所有圆角都太小”，而是三类：

1. **图标选中态把图标本身弄没了**：双击后图标整块变黑，图标字形也仍是深色，像禁用/卡死。
2. **窗口关闭/最小化按钮画成了“拱门 + 两条腿”**：圆角被实际尺寸、标题栏高度和阴影挤掉。
3. **角标与少数控件没有统一的圆角语言**：图标计数角标是 6px 圆角方形，Web 是药丸/圆形；checkbox 是硬方角。

不建议“把所有东西都改成胶囊”。窗口 13、卡片/图标 11、按钮 8 这套基础 token 是对的；需要修的是**选中态、控件几何、角标体系**和少数一次性数值。

## 2. U1：双击图标全黑（P0）

### 2.1 现象

- 双击左侧任一桌面图标（推演器、档案、线索册等）后，应用窗打开。
- 图标块进入选中态：44×44 的底板变成近黑色，标签也变成深色药丸。
- 但图标字形仍然是深色，叠在深色底板上几乎看不见，观感就是“整块全黑”。
- 点画布空白处也不会恢复；只有再点另一个图标才会把前一个取消选中。

### 2.2 根因

**(A) 深色 SVG 不能被 `modulate` 提亮**

`DeskIcon` 选中时执行：

```gdscript
_icon.modulate = TecTheme.CARD if dark else Color.WHITE
```

`modulate` 是**乘法**，不是替换颜色。图标资源本身是深色实心：

```svg
fill="#2b2b26"
```

例如 `assets/icons/star.svg`、`users.svg`、`clipboard-list.svg` 等全部是深色填充。深色乘以暖白仍然接近深色，所以选中后图标字形不会变成奶油色，而是继续是深色，和深色底板糊在一起。

Web 那边不是这样：SVG 使用 `fill="currentColor"`，选中态的 CSS 把 `color` 设为 `var(--card)`，字形自然翻成奶油色。参见 `index.html:959` 和 `.desk-icon.sel .icon-glyph{color:var(--card)}`。

**(B) 图标选中态没有清除路径**

`Desktop._on_icon_pressed()` 的第二次点击只做 `_open_icon_app(app)`，没有清空 `_icon_sel`：

- `Desktop.gd:1108-1129`：单击选中；双击开窗；没有 `deselect`。
- `Desktop.gd:2162-2169`：`_clear_selection()` 只清节点选中，而且 `_selected == ""` 时直接 `return`；即使点画布空白，也不会碰 `_icon_sel`。

所以图标会一直保持 `.sel`，直到点另一个图标。Web 的 `clearSelection()` 会同时清 `.node.sel` 和 `.desk-icon.sel`，这是行为差异。

### 2.3 建议

**优先做 A+B，不要只改颜色。**

1. **把图标资源统一成可染色 mask**：所有 `assets/icons/*.svg` 的 `fill` 改成白色（或导入成纯 alpha 图标）。
   - 正常态：`_icon.modulate = TecTheme.LINE`（深墨色）。
   - 选中/按下/落点态：`_icon.modulate = TecTheme.CARD`（奶油色）。
   - 这样深色底板 + 奶油字形，和 Web 的 currentColor 语义一致。
   - 该资源目录目前只被桌面图标使用（`Desktop.gd:961/985/995`），改色风险可控。
2. 如果不想动 11 个 SVG，可加一个极简 colorize shader：用纹理 alpha 当遮罩，输出统一 `icon_color`。但这会比直接规范资源多一层材质管理。
3. **开窗后清选中**：在 `_open_icon_app(app)` 成功打开后调用 `_select_icon(null)`，或新增 `_clear_icon_selection()`。
4. **空白点击也清图标**：`_clear_selection()` 在 `_selected == ""` 的早退之前先处理 `_icon_sel`。
5. 如果希望保留“当前应用”提示，不要整块反黑；改用底部 2px 墨线、左上小方点或描边。选中态只用于“单击查看”，不用于“已经打开”。

### 2.4 验收

- 双击任一图标：窗打开；图标字形仍清晰可读；不再出现深色字压在深色底板上。
- 点画布空白：节点选中和图标选中一起消失。
- 单击图标仍保留选中反馈；双击打开后不残留“全黑”状态。
- 选中态与普通态的图标字形对比度 ≥ 4.5:1（奶油字/墨底）。
- `test_p26.gd` 的双击开窗断言仍通过，并补一条“双击后图标不再处于选中态”。

## 3. U2 + U8：关闭/最小化按钮（P0）

### 3.1 现象

Godot 右上角的 `–` / `×` 看起来像两个**拱门**：

- 顶部有圆角；
- 左右两条竖边一直落到标题栏底；
- 底部圆角缺失，像被切平；
- `–` 和 `×` 明显偏下，不在按钮视觉中心。

Web 参考是完整的圆角方形按钮，底部有清楚的留白和阴影，字形居中。

### 3.2 根因

1. **标题栏高度不足**  
   Godot `SysWindow.BAR_H = 23`，Web `.syswin-bar` 是 `padding:5px 6px` + 18px 按钮 = **28px** 内容高。Godot 的按钮上下只剩约 2px 留白，底边几乎贴住栏底。

2. **Button 被最小尺寸顶高**  
   `_mini_button()` 里 `b.size = 18×18`，但 Button 的最小尺寸受字体行高/主题影响，实际绘制高度会被撑大；18px 宽 × 略高于 18px 的形状，圆角自然变成“上下圆、两侧直”的拱门。

3. **阴影没有足够空间**  
   `normal.shadow_size = 3`、`shadow_offset = (1,2)`，在 23px 栏高里把底边和下方留白一起压掉。

4. **字形用字体直接绘制**  
   `–` / `×` 作为 Button.text 绘制，受点阵字体基线和行高影响整体偏下；Web 用固定 `line-height:16px`，所以视觉居中。

### 3.3 建议

- 标题栏恢复到 **26–28px**；若保持窗口总高不变，从 body 顶部让 3–5px。
- 控件固定为 **18×18 正方形**；不要依赖 `size` 硬压，改用空文本 Button + 居中 Label，或自绘 Control，确保实际矩形就是 18×18。
- 三个状态（normal/hover/pressed）使用**相同 content margin**，避免 hover 时字形跳动。
- 阴影收到 **1–2px**，或去掉小控件的外阴影；小按钮用 1px 描边 + 顶部 1px 高光就够。
- `–` / `×` 用 2px 线段或子 Label 居中绘制，不依赖字体基线。
- 如果追求“完全圆”，用 **20×20 / r10**；如果保持 Web 口径，用 **18×18 / r7**。注意 Web 的 r7 是圆角方形，不是正圆。
- `MemCard.gd:127-129` 的关闭按钮现在是 `r4`，与普通窗 `r7` 不一致；统一到同一个控制 token。

### 3.4 验收

- 960×560、1280×720、1920×1080 三档下，按钮四角完整，无“腿”。
- `–` / `×` 在按钮几何中心，水平/垂直偏差 ≤ 1px。
- hover 反色、pressed 下陷不改变按钮外框位置。
- 记忆卡暗色主题下按钮仍完整，半径/字形与普通窗一致。

## 4. U3 + U4：角标体系（P1）

### 4.1 现状

- `Desktop._make_badge()` 使用 `TecTheme.flat(..., 6, ...)`：圆角 6px 的方形。日志未读、推演器、证物袋、线索册、花园、地图“已关闭”、档案“新”都会走这里。
- Web `.badge` 使用 `border-radius:999px`，是药丸/圆形。
- `NodeCard` 的“新”是 `20×19 / r9`，已经接近圆，但 12px 字没有内边距，文字贴边。
- `NodeCard` 的“无文本入口”66×19/r9、“已固定”42×19/r9 是药丸，方向正确。
- `CaseMapWin` 状态角标 58×24，代码里先 `R_BTN` 再强制 `set_corner_radius_all(12)`；12 正好是半高，视觉是药丸，但硬编码。

### 4.2 建议

- 新增明确 token：
  - `R_BADGE` 不设固定值，按高度取半：`corner_radius = floor(height / 2)`。
  - 18px 高 → 9；20px 高 → 10；24px 高 → 12。
- 图标角标从 6 改为 **9**（或动态半高），保持 1px 描边、深底奶油字。
- 单字角标（“新”、“6”）可以做成正圆：宽高相等 + 半径半高。
- 多字角标（“已固定”、“无文本入口”、“已关闭”）用药丸：左右 5–6px、上下 2px 内边距；不要用 12px 字硬塞进 20px 宽。
- 卡片“新”建议 **22×20 + 左右 2px 内边距**；若坚持 20×19，至少把文字 `clip_text` 和 `content_margin` 显式设置，避免贴边。
- CaseMap 状态角标改为动态半高，不写死 12。
- 不要为了贴近 Web 把字号改成 9.5：项目点阵字体必须落在 12 的整数倍；用盒子尺寸解决。

### 4.3 验收

- 所有角标外轮廓在视觉上连续，没有 6px 方角的“半圆半方”。
- 单字角标是圆/药丸；多字角标文字不贴边、不裁字。
- 卡片“新”、地图“已关闭”、档案“新”、日志未读在同一屏内圆角语言一致。
- 角标不遮挡卡片标题/图标；紧凑模式下位置仍正确。

## 5. U5：页眉 checkbox（P1）

### 5.1 现状

`Desktop._check_tex()` 现画 13×13 的硬方角：

- 勾选：整块奶油底 + 深色阶梯勾；
- 未勾选：四边 1px 奶油描边。

Web 使用原生 checkbox + `accent-color`，外框有 2–3px 圆角。当前 Godot 页眉里所有按钮/开关都是圆角，只有 checkbox 是直角，容易被看成“没做完”。

### 5.2 建议

- 仍是 13×13，在 `_check_tex()` 里把外框画成 **2–3px 圆角**。
- 勾选态：奶油填充 + 圆角；未勾选：透明底 + 圆角 1px 描边。
- 保持勾的 2px 阶梯，不缩放、不模糊。
- 如果担心 1x 下圆角太小，最少给 2px；不要做成 999 胶囊。

### 5.3 验收

- 三个开关的 checkbox 外框圆角一致，勾仍清晰。
- 选中/未选中切换不改变 13×13 外框位置。
- 与 Web 页眉截图并排时，方角差异消失。

## 7. U7：页眉证章方角（P3，设计取舍）

`Desktop.gd:615-635` 明确使用 `r0`，Web `#inv-chip` 也没有圆角。它不是移植遗漏，而是“档案标签/证章”的语义。

建议：

- **保留方角**，但把它做成明确的“章”：双层细边框、内缩 1px、字距略大；这样它和其他圆角控件区分开，不会像漏改。
- 如果用户明确希望整体更圆，给 **2–3px** 即可，不要给 8px 胶囊——那会变成普通按钮。
- 不要因为“统一圆角”把滚动条、日志错误行、证章全部磨圆；这些方角是 Web 原有语言。

## 8. 执行顺序

当前状态：**U1–U6 已完成，U7 已复核保留方角，U8 随 U2 修复（2026-10-22，1168 项全绿）**。

原则：**先修“看起来坏了”的独立问题 → 再动影响全局布局的窗口标题栏 → 再做角标/开关 → 最后做主观风格**。每批单独改、单独截图、单独回归，避免一次改太多导致问题无法定位。

```text
0 基线 → 1 U1 图标全黑 → 2 U2+U8 窗口控制
      → 3 U3+U4 角标 → 4 U5 checkbox
      → 5 U6 一次性半径 → 6 U7 证章 → 7 收尾
```

|---|---|---|---|---|

| 7 | **收尾**：全套测试 + 三档截图 + P3 并排 + 更新本文档状态 | 1–6 | 全部相关文件 | 全绿；U1–U6 三档截图确认；文档勾选完成 |

### 8.1 顺序理由

- **U1 先做**：只碰图标资源和选中逻辑，和窗口布局解耦；它也是视觉上最像“坏了”的问题，先单独验收。
- **U2+U8 第二**：标题栏高度/按钮几何会影响所有窗口截图；先定下来，后续角标和 checkbox 的并排检查不会返工。
- **U3+U4 第三**：角标 token 依赖前一步稳定的标题栏/截图基准；“新”角标依赖 U3 的半高规则。
- **U5 第四**：独立小改，放在主几何稳定后做，避免页眉截图反复重拍。
- **U6 第五**：一次性半径是收口项，等控制/按钮 token 定稿后再统一替换。
- **U7 最后**：证章是主观风格选择，等整体圆角语言确定后再决定是否保留方角。
- **每批建议单独 commit**：若截图回归异常，可以只回滚该批，不影响已验收项。

### 8.2 不建议的顺序

- 不要先批量把所有 `r6` 改成 `r9`：图标角标、行、输入框的语义不同，先统一数值会把问题从“方形”变成“全胶囊”。
- 不要先改角标再改标题栏：窗口控制会改变整屏截图基准，角标对拍容易白做。

# 单色改版计划（System 1 骨架 + 印刷专色）

> 目标：把桌布、窗体、卡片、图标、连线整套配色从「柔和浮雕暖米色」改成参考图的
> **黑白 + 抖动纹理骨架**（Macintosh System 1，1984），并用「套色印刷」的方式
> **保留语义色彩**——色彩只作为少量专色，不出现在结构与大面积上。
> 范围：`ydgodot/`（Godot 移植版）。Web 原型不在本次范围内，见 §9。

---

## 1. 参考图拆解：目标视觉语言

| 角色 | 参考图取值 | 说明 |
|---|---|---|
| 墨 `INK` | `#000000` | 边框、文字、图标轮廓、菜单栏字 |
| 纸 `PAPER` | `#FFFFFF`（本项目取 `#FBFAF5`） | 窗面、卡面、按钮面、菜单栏底 |
| 桌布 | `#000`/`#FFF` 的 **1px 网点** | 采样实测：原生 1x 下逐像素交替，**不是真灰值**，是 50% 网点 |
| 次级填充 | 25% / 75% 网点 | 按钮面、滑杆槽、非活动区 |
| 标题栏 | 细横纹（1px 黑 + 2px 白） | Control Panel 那扇窗的招牌特征 |
| 圆角 | 4~5px，**阶梯状**（无抗锯齿） | 不是现在的柔和 13px |
| 投影 | 无软影 | 现在的 14px 高斯影要拿掉 |

**关键判断**：参考图里没有任何真正的灰值。所有"灰"都是黑白像素的排布密度。
所以骨架改造的本质是 **「把颜色换成图案」**，不是「把色值调灰」。

## 4. 配色方案（**V3：纯 1-bit**，2026-10-23 二次修订；V1/V2 均被实测推翻，见 §4.4）

> V1 写的是「纸白 `#FBFAF5` + 25% 网点桌布 + 文字一律纯黑」。三条都在实测里被推翻了：
> 网点在 1x 屏上是灰砂、纸白仍有暖调、次要文字全黑会让层级塌成一片。V2 换成下面的方案。

### 4.1 骨架三层（**这是整个方案的地基**）

| 层 | 色 | 占屏 | 承担 |
|---|---|---|---|
| 外壳 | `#DDDDDD` | ~5% | 图标栏底、窗框（`bg`）、桌底、次级面板 / 按钮底 |
| 画布 | `#8A8A8A` | ~75% | 节点画布（`stage_bg`）—— **全屏唯一的大面积灰** |
| 面 | `#FFFFFF` | ~5% | 卡片、窗口内容区 |
| 结构 | `#000000` | ~7% | 一切文字、1px 框线、图标、页眉 / 状态条 |

**两条硬规律**

1. **外壳必须比画布浅。** 反过来的话，12px 的黑色图标与文字压在外壳上就没有立足点
   （黑图标 vs `#6E6E6E` 只有 2.9:1，图标栏直接糊掉）。所以「桌面深、窗口浅」这条
   Mac 常识在这里要反过来用 —— 我们的画布才是「桌面」。
2. **窗框不发白，用外壳同色。** 白框包灰画布会读成「一张纸的边缘」，而这里要的是
   「灰桌面里嵌了一块中灰垫板」。窗与桌的层次由 **1px 黑框**承担，不靠投影和圆角。

### 4.3 专色红线（修订为五条）

1. **面积**：任一屏的彩色像素 < 3%（类型符号 9×9、2px 框线天然达标）。**灰阶不算专色**，
   画布 75% 的中灰不是问题。
2. **禁用位置**：大面积底色、卡片/窗体的常规边框、正文、投影。
3. **必须有黑白冗余**：每个专色位都配一个不靠颜色的区分手段（形状 / 线宽 / 虚实 / 反白）。
4. **不用渐变、不用真光晕**：只用实色。
5. ~~文字一律纯黑~~ → **次要文字只准用 `INK_MUTED`（对外壳 ≥ 4.5:1），不许更浅**。
   实测：全黑会让「标题 / 副标 / 元信息」三层塌成一层，可读性反而下降。

### 4.4 V3 终版：三层灰阶也塌了 —— 只剩一层（2026-10-23 二次修订）

V2 的三层灰阶同样没站住。实测截图里 **外壳 `#DDDDDD` / 画布 `#8A8A8A` / 面 `#FFFFFF` 叠在一起，
窗口、卡片、图标栏互相糊**（用户原话：融合度太差）。而参考图根本不是灰阶 ——
System Folder 是**纯 1-bit：白底 + 黑线**，一个中间灰都没有。

| 层 | V2 | **V3** |
|---|---|---|
| 外壳（图标栏 / 窗框 / 桌底） | `#DDDDDD` | `#FFFFFF` |
| 画布（`stage_bg`） | `#8A8A8A` | `#FFFFFF` |
| 面（卡片 / 窗口内容） | `#FFFFFF` | `#FFFFFF` |
| 结构（文字 / 线 / 图标） | `#000000` | `#000000` |
| 次要文字 | `#5A5A5A` | `#000000` |

**分层不再靠色阶，只剩三条轴**：

1. **线宽** —— 卡片 1px / 窗口 2px / 点亮 2px 粗框
2. **线型** —— 实线（已探索）/ 虚线（未探索、已折叠）/ 双线（枢纽）
3. **反白** —— 已捕获线索、拖动目标、图标选中

配套改动：

- 圆角全部归零（`R_WIN/R_SM/R_BTN` 13/11/8 → 0/0/0）；`StyleBoxFlat.anti_aliasing` 关；
  > ⚠ **P4.1 已推翻这一条**：圆角改按零件分级、AA 也开回来了（见 §6 P4）——
  > 「全直角 + 关 AA」正是用户说的「太锐利」，配套的粗线图标也被否掉了。
  `surface.gdshader` 的描边从 `smoothstep` 软过渡改成 `step` 环带
- **删掉所有柔光**：卡片无渐变/无高光/无投影、图标无底板、点亮无金色光晕
- 图标：**底板消失**，黑色线稿直接浮在桌面上（照参考图）；选中 / 悬停 = 整块反白
- 标题栏两侧：一条 30% 灰线 → **三道 1px 纯黑横纹**（照参考图）
- 连线四态全黑：entity 1px 实 / move 2px 实 / cond 2px 虚 / tried 1px 长虚

**代价**：窗口叠窗口时，「谁压着谁」只剩边框粗细一条线索。Mac 原本靠**桌面 pattern**
解决这件事，但用户明确不要网点（见 §6 P1 的密度阶梯结论），所以此处靠 1px / 2px 硬扛。

**连续缩放的像素代价**：卡片跟随相机做 0.62~1.3x 连续缩放，1px 硬边落在非整数像素上
必然出一圈淡灰。`body` 用 `smoothstep(-0.5, 0.5, d)`（半像素过渡）而不是 `step(0, d)`，
让它至少稳定占满一个像素 —— 视觉上仍是硬边。

### 4.5 字体：换成 SIL OFL 的缝合像素字体（中英文同源）

原来 `assets/raw/font.ttf` 是 **VonwaonBitmap 12px（凤凰点阵体）**，作者 Haoyu Qiu
以 **CC0 1.0** 发布（公有领域，可商用，name 表里写着 "No rights reserved"）。
**许可本来就没问题**，问题在字形：

- 凤凰的中文是**宋体点阵** —— 横细竖粗、笔画有收笔
- 参考图的 Chicago 是**无衬线**
- 两者同屏，一个字有收笔、一个字没有，这就是「字体不统一」的来源

换成 **缝合像素字体 / Fusion Pixel Font 12px 比例版（简体）**：

| 项 | 值 |
|---|---|
| 文件 | `assets/raw/font-fusion.woff2`（945 KB） |
| 许可 | **SIL OFL 1.1**，全文 `assets/raw/font-fusion-OFL.txt`；保留字体名 "缝合像素 / Fusion Pixel" |
| 规格 | 12×12 点阵、黑体无衬线、中英文同源、比例模式 |
| 字源 | 方舟像素 10/12px + 美咲 + 美绩 + 精品点阵 7×7/9×9 + 俐方体 11 号 + Galmuri（全部 OFL 或与之兼容） |

渲染口径不变：**关抗锯齿 / 关 hinting / 关次像素 / `oversampling = 1.0`**。
字号仍是 12 的倍数（字宽变化不影响字号档位），但西文变宽，标题栏 `SPACING_GLYPH` 从 2 收到 1。

**为什么不用 Chicago 的复刻**：Chicago / Geneva 的复刻（ChiKareGo、FLF 系列）许可多为
非标准 freeware，且只覆盖拉丁 —— 中文还得再配一套，反而更「不统一」。一套覆盖中英文、
许可清晰的 OFL 字体，比字形更接近但许可含糊的复刻更可靠。

### 4.6 图标语言：细线稿 × 2 栅格，不是粗线点阵

图标换了两次，最终方案是**回到原来的 24×24 细线稿**，只改栅格化倍率：

| 项 | 值 |
|---|---|
| 源文件 | `assets/icons/*.svg`，24×24，`fill="#ffffff"`（白色 mask，颜色由 `DeskIcon.modulate` 给） |
| 栅格化 | `.import` 里 `svg/scale = 2.0` ⇒ 纹理 **48×48**，线宽 2px |
| 显示 | `DeskIcon.GLYPH_SIZE = 48`，与纹理 **1:1**，NEAREST 完全不重采样 |
| 底板 | **没有**。普通态连底板节点都不画（摘下 material，用桌面色平涂）；选中/落点才挂回 shader 出黑色圆角块 |

**两次方向都错在哪**：

1. **原方案（24px 纹理 → 44px 显示）**：1.83 倍最近邻放大，1px 线被抽成 1px/2px 交替，
   线宽处处不等 —— 这是「图标看着发毛」的技术原因。
2. **P4 初版（44×44 粗线点阵）**：为了解决重采样，把图标重画成 22×22 字符点阵 × 2px。
   线宽是统一了，但**丢掉了图形本身**（星形变十字、音符变锤子），而且满屏粗黑块
   与「太锐利」的观感直接相关。用户否掉了这一版。

**结论**：问题出在**缩放**，不在图形。把显示尺寸对齐栅格化尺寸（48 = 48）之后，
原来的细线稿就够清楚了，不需要重画。

⚠ 改图标时：`GLYPH_SIZE`、`.import` 的 `svg/scale`、SVG 的 `width/height` 三者必须
满足 `width × svg_scale == GLYPH_SIZE`，否则又回到非整数重采样。

## 5. 状态语义映射表

**这是最容易做砸的地方** —— 六种状态必须各有独立的表达，且不能互相撞车。
下面这张表是后续所有代码的判据，改完逐行核对。

| 状态 | 现在的表达 | 1-bit + 专色方案 | 用色 |
|---|---|---|---|
| 普通（已探索） | 米白渐变 + 发丝褐边 | **纸白底 + 1px 实线黑框** | — |
| 未探索 | 虚线边 | 1px 黑虚线（周期 3-3） | — |
| 枢纽 | 双线边 | 1px 双线（间隔 2px） | — |
| 点亮（可当工具） | 金框 + 暖白底 + 黄光晕 | **2px 琥珀框 + 琥珀网点光晕 + 纸白底** | 琥珀 |
| 已捕获 | 深反白 `#38372f→#1f1f19` | **满黑底 + 纸白字**；类型符号用提亮版 | 提亮专色 |
| 选中 | 2px 墨环外扩 2px | 1px 黑实线外扩环 | — |
| 拖动目标 | 悬停高亮 | 2px 黑粗虚线框 | — |
| 缩略档（低倍率） | 类型色符号铺满 | **专色 50% 网点块**（按类型不同色相） | 专色网点 |
| 无关卡淡化 | `modulate.a = 0.32` | **保留 alpha 不动**（严格 1-bit 该用稀疏网点，但那是渲染路径改造，单独一轮） | — |
| 类型（地点/物品/人物） | 3 种颜色 | 3 种颜色保留，但**只涂 9×9 符号**；形状冗余已有 | 三色 |

**互撞检查**：
- 点亮（琥珀 2px 粗框）≠ 已捕获（满黑底）≠ 枢纽（黑双线）≠ 选中（黑外扩环）—— 四者互不重叠。
- 琥珀 vs 赭：`#A86A12` 与 `#8F4520` 同属暖橙区间，**相邻时会混**。缓解：类型符号只有 9px、
  点亮框是 2px 线，形态差异大；另外琥珀只出现在"被点亮"这一种状态，语义上下文强。

**为什么放弃网点（实测结论，不是口味）**：做了五档密度阶梯，同一块 280×120 桌布、1x 与 3× 各看一遍 ——

| 档位 | 1x 观感 |
|---|---|
| `2px / 25%`（原方案） | 一层灰砂 |
| `4px / 6.25%` | 「网点纸」，仍然是纸 |
| `6px / 2.8%` | **零星黑点，比原方案更脏** |
| 灰底 `#808080` + 2px 深灰点 | 干净 —— 但已等价于平涂 |
| **平涂** | 干净 |

结论：**拉大点距救不了它**，只是把「砂纸」换成「网点纸」，`6px` 那档反而像脏纸。
真正有效的是**降对比**或直接平涂。参考图（Mac OS 8 启动画面）看着是「均匀的中灰」，
但采样下来桌面是 `#787878` / `#888888` 的 4px 网点 —— **两色对比只有 6%**，
所以肉眼读作平涂。这层窗户纸不值得在 1x 屏上复刻。

**由此得到的通用规则**：**纹理是标点符号，不是背景。**
大面积（桌布）零纹理；窄条（标题栏横纹、进度条、滚动槽）才铺纹理。
`mono_pattern.gdshader` 因此**不废弃**，改挂到这些小面积处。

**亮度取值**：`#8A8A8A` 而非参考图的 `#808080` —— 参考图是 CRT，有余晖加成，
现代屏上 `#808080` 会发闷。对卡片白 3.2:1，白卡浮得起来又不压过类型专色。

`test_ui` 改为 4 项 P1 断言（220 项 / 0 失败），全套 15 脚本 **1278 项 / 0 失败**。

在灰底上比什么都显眼。不去掉它，前面几轮的去黄等于没做。

### P4b · 按钮语法统一 + 图标按下态（✅ 2026-10-23 完成 · **V4.2 修正版**）

V4.1 验收后用户的第二批评判，两条：

> 1、按钮应该全部统一成这种模式。案件地图里面的按钮，尤其明显没有改。
> 2、桌面图标按下去以后，应该是按照图的样子全黑，而不是多一个框出来的全黑。

参考图（System 6 Control Panel）里其实只有**两种**键，都不是黑底：

- **Set**（普通键）= 白底 + **1px 纯黑键线** + 小圆角 + 黑字；
- **Find**（默认键）= 同上，里侧再套一条**内键线**（外框 + 约 3px 留白 + 内框）。

「案件地图尤其明显没改」的根因不在圆角，在**键线浓度**：`flat()` 的 `border_col`
默认取 `EDGE`，而 `EDGE` 一直是 `Color(0,0,0,0.30)`（柔和浮雕期的遗产）。
30% 的黑在白底上读作浅灰，于是那扇窗里 34px 的小方块、状态牌、行框整片「像没做单色改版」。

| P4b.1 | `EDGE : 30% 黑 → INK`（纯黑）。层次仍靠**线宽**：窗口 2px / 其余 1px。`EDGE_SOFT`（18%）保留，专给「锁定 / 不可聚焦」这类**有语义的**降浓度 | ✅ 头像框、输入框、案件行、矩阵小牌一次全转黑 |
| P4b.2 | `button_style()` 重写：白底 + 1px `INK` + `R_BTN`；悬停 **2px**（只加粗键线，不改填充）；按下**反白**（`INK` 底 + `CARD` 字）。字色跟着填充走，悬停不改字色 | ✅ 不再用 `EDGE`，也不再出现灰填充 |
| P4b.3 | `primary_button()` = 同一条键线 + **内键线**（`TecTheme.keyline_ring(host, inset, radius)`，用子 `Panel` 画第二道 border，因为一个 StyleBox 只能画一道）。不再填黑 —— 黑底是「深色面」的语法（标题栏 / 已捕获态），不属于按钮 | ✅ 与参考图的 Find 一致 |
| P4b.4 | 次级键同步：`SysWindow._mini_button`（– / ×）、`CaseMapWin` 的行 / 小方块 / 状态牌、`Desktop._build_case_park` 的抽屉卡片。所有「悬停 = `CARD → BG`」的假反馈（两色都是纯白）改成**键线 1px → 2px** | ✅ |

中间夹一道白缝。参考图里按下只反白标签，图标本身仍是黑线躺在桌面上。

## 7. 风险与对策

| # | 风险 | 说明 | 对策 |
|---|---|---|---|
| R1 | 网点出摩尔纹 | 窗口缩放 / 非整数 DPI 时半像素采样 | `stretch/mode` 已是 `disabled`（逻辑=物理像素），`floor(FRAGCOORD/cell)` 对齐；P1.3 专项验收 |

| R3 | 专色变"脏点" | 纯黑白底上，低饱和中间调专色会显脏 | 专色一律提纯压暗（§4.2 已重算），并限制面积 < 3% |
| R4 | 琥珀与赭（物品）相邻时混淆 | 同属暖橙区间 | 形态差异（2px 线 vs 9px 方块）+ 语义上下文；必要时琥珀再压一档到 `#8F5A0C` |
| R5 | `MUTED → INK` 后界面变吵 | 面包屑/时间戳/副标题失去层级 | P4.4 用排版补偿（分隔线/缩进/方括号），不是简单换色 |
| R6 | 115 处硬编码漏改 | 逐个找必漏 | P0.4 脚本审计 + `mono_audit.py --check` 作为准入门槛 |
| R7 | 烘焙窗框作废 | `win_frame.png` 花了大功夫对拍 | 文件保留；`_uses_baked_frame()` 留成开关，随时可切回对比 |
| R8 | Web 对拍基线（2.30%）失效 | Web 仍是米色，截图对拍不能再用 | 明示作废；若要保留需同步改 Web（§9） |
| R9 | 中文点阵在纯黑白下过粗 | 12px 字 + 1px 描边容易糊成块 | 正文与边框之间留 ≥6px 内边距；`PAD 8` 可能加到 10 |

## 8. 建议的推进节奏

```
P0 地基 ──► P1 桌布 ──► P2 窗体 ──► P3 卡片 ──► 【样张闸门】──► P4~P6 ──► P7 验收
 (纯 diff=0)   1 处        1 处杠杆      6 处       看整屏判断       逐窗替换      回归+文档
```

- **P0 + P1 + P2 + P3 就能看到 80% 的效果**，也是判断"这条路对不对"的最小成本。
- P4~P6 是铺量，机械但量大（115 处）；P4.4 的排版补偿是唯一需要动脑的部分。
- 每阶段一次提交，便于单独回滚。

## 1. 总循环

```text
场景/物品 ──TEC分析──> 线索（五感）──> 推演桌布 ──> 结局/真名          【感知渠道，现状】
物品/场景 ──TEC分析──> 证据「物」（原料）──┐
对话/独白/回忆 ──首次完整播放──> 证据「词」（原料）──┴──组合──> 证据「证」（结论）
                                                            │
                                                  证物袋归档 / 拖到档案卡字段
                                                            │
                                              主张（待核对）──TEC批量核对──> 对：盖章 / 错：退回
                                                            │
                                              字段集齐 ──> 掉落人物线索（落地即已捕获）
```

**字牌三分（2026-10-25 用户定稿）**：「**物**」（物证原料）×「**词**」（言词证据）→「**证**」（结论）。
字牌即规则：物和词只是原料，**只有「证」能填进档案卡字段**——组合从可选变成必要。

线索分类学（与「捕获统一 TEC」不冲突）：**TEC 捕获现场的秘密（物证线索），档案产出调查员的结论（人物线索）**——
前者是捕获，后者是演绎，掉落的人物线索落地即已捕获，无需再过 TEC。

## 2. 「证据」节点类型（evidence）

### 2.1 立项依据（三检验全过）

1. 独立消费渠道：线索喂推演桌布（感知），证据喂档案卡字段（物证），互不混喂；
2. 独立收纳位：证据进**证物袋**——证物袋从「物品临时停车场」升级为「档案证据夹」；
3. 独立视觉身份：见 §2.3（按用户定稿，与现有卡片对齐 + 「证」字标识，**不新增形状**）。

### 2.2 数据

- `core/defs/EvidenceDef.gd`：`id / label / desc / tier`（`"wu"` 物 / `"ci"` 词 / `"zheng"` 证）
  （+ 可选 `source_text`：合成时的一句话说明）。
- **物**的产出：物品/场景定义上加 `hidden_evidence`（与 `hidden_clue` 并列），TEC 分析时一并掉落；
- **词**的产出：`DialogueDef` 加结构化字段 `drops_evidence`（→ 词级 EvidenceDef id），
  **首次完整播放完才掉落**（打字被补全跳过的不算首次完整播放），重播不重复；
- **证**的产出：只来自合成配方（§3）。
- 配方表：`core/defs/EvidenceRecipeDef.gd`：`a / b / evidence / text`（无序对）；
  挂在案件层（`CaseDef.evidence_recipes`），资源落 `cases/<case>/evidence/*.tres`，
  迁移/装载走 `CaseLoader` 与 `json_to_tres.gd` 既有管线。
- **不进正文**（内容层总纲：content 只负责纯文字）。

### 2.3 视觉识别（用户定稿：与节点现状对齐 + 字牌三分）

- 卡片本体与现有节点卡**完全同规格**：同一尺寸档、同一边框状态语法（实线/虚线/双线/金框/反白）、
  同一 8px 网格、同一 pop 入场。
- 识别标识：**标题前的墨色反白字牌**，按 tier 显示「**物**」「**词**」「**证**」一字——
  落在 KindGlyph 的槽位上（证据族没有五类形状语义的负担，类型字牌位让给这枚印章式标识）；
  缩略档下字牌放大、文字退场（沿用 LOD 规则）。
- 字牌即规则的教学红利：「物 × 词 → 证」的合成代数从字牌上就能读出来，TEC 的教学台词只需点一次。
- 不设「已捕获」深色反白态（证据族没有捕获概念）；其余状态（选中环/悬停/拖动/淡化）全部沿用。

### 2.4 行为与落点规则

| 场景 | 物 | 词 | 证 |
|---|---|---|---|
| 产出 | TEC 分析物品/场景（`hidden_evidence`） | 对话/独白/回忆首次完整播放掉落 | 只由链式合成产出 |
| 单击 / 双击 | 单击 = 选中 + 详情；双击 = 无额外动作（三者同） | 同左 | 同左 |
| 证物袋 | ✅ | ✅ | ✅ |
| 线索册 | ❌「证据不归线索册——它属于证物袋」 | 同左 | 同左 |
| 推演桌布 | ❌「桌布只接五感线索」 | 同左 | 同左 |
| TEC | ❌（它就是我分析出来的） | ❌「话是你说给我听的，不用分析」 | ❌「结论 already 是结论」 |
| 对话窗 | ❌（不是人物） | ❌ | ❌ |
| 档案卡字段 | ❌「这只是原料——把它和证词拼出结论再说」 | ❌ 同左 | ✅ 主张（§4） |
| 画布组合 | ✅（§3） | ✅ | ✅（证×物 可继续上链） |

## 3. 链式两两合成

**不做真 N 元堆叠**（叠放次序/拆开/误触都是新 UI 负担）；用现有的「拖到另一节点上」 pairwise 语法，
推理深度由**链式中间产物**提供：

```text
手写笔记 × 台灯              → 证「台灯下的字迹」   （物×物，允许）
「台灯下的字迹」 × 陆珩松的证词 → 证「伪造的时间」   （签名配方：物×词）
证「伪造的时间」 × 手机        → 证「谎言的时刻」     （证×物，链式上延）
```

- **签名配方 = 物 × 词 → 证**（物证要拿证词来印证，这是侦探纪律）：教学与 TEC 台词都按它讲；
  同时允许 物×物、证×物（由配方表逐条定义），链条深度控制在一案 2–3 层，再深玩家追丢。
- 匹配走 `ComboSystem` 新增的证据配方段：无序对命中 `evidence_recipes`；未命中照旧记 `tried` 虚线。
- 产物在目标节点右下 `(60 + i*26)` 撒开（沿用反应表产物的落位规则）+ pop 入场 + 「新」角标。
- 成功反馈：toast + 日志（现有通道），证据卡的 `desc`/`source_text` 在详情窗可读。
- **可靠性钩子**：「词」可能撒谎——配方可限定 tier（如「推翻不在场证明」必须 证词×物证，两个原料缺一不可）；
  纯「词」支撑的主张核对时，TEC 给一句「他只说了这些——但话可以撒谎」。

## 4. 档案卡字段：主张 → 核对 → 盖章

### 4.1 字段三层（定稿）

| 层 | 字段 | 填写方式 |
|---|---|---|
| 自动 | 姓名 / 首次记录 / 照片 / 编号 | 系统（遇见即记） |
| 半自动 | 身份/职业、关联 | 「写着答案」的物证经 TEC 分析后直填 |
| **关键** | **死因、真名级字段** | **词库选择 + 证据支撑**（Obra Dinn 式），必须过核对 |

### 4.2 主张（玩家操作）

- 把证据卡拖到档案卡的**关键字段行**上 = 提出主张：字段进入**待核对态**（虚线框 + 「待核对」小牌，墨色——不预先染专色）。
- 关键字段还需从**词库**选一个值（如死因：窒息/中毒/坠落/刺伤……，词库随案件数据配）；
  主张成立的条件 = 词库选对 **且** 附上的证据能支撑。词库本身就是提示结构（答案必在列表中），但不告诉你是哪个。

### 4.3 核对（TEC 担任，批量节奏）

- **不逐条判对错**：主张攒够 2–3 条（或玩家主动点「请 TEC 核对」）才统一核对——
  对的**盖核准印章**（警示朱，`SPOT_DANGER` 的既有「核准印章」语义首次登场），错的退回并给一句不剧透的提示。
- 防穷举：词库盲选 + 证据乱贴的组合，核对不过就是不过；「攒一波交批阅」的悬念节拍是刻意的。

### 4.4 完成与产出

- 关键字段全部盖章 → **人物线索掉落**画布（pop 入场 + 「新」角标 + 落地即已捕获）。
- **G14 提醒时机**：若掉落的是真名级线索，该条 TEC 核对台词用「强调青行首符号 + 反白行 + 打字机停顿」
  （口径见 `UX_FLOW_PLAN.md` G14）。

## 8. 验收断言清单（无头）

- 配方命中：拖 A 到 B 产出正确证据卡（位置撒开/pop/「新」角标）；无序对两种方向都命中；未命中记 tried。
- 字牌三态：物/词/证卡的字牌字符正确、1x 清晰、缩略档正确退场。
- 词卡掉落时机：对话/独白**补全跳过不掉落**、首次完整播放掉落、重播不重复。
- 落点规则：物/词/证 → 袋 ✅、→ 册 ❌、→ 桌布 ❌、→ TEC ❌、物/词 → 字段 ❌（原料话术）、**证 → 字段 ✅**（话术逐条断言）。
- 主张/核对：错误词库退回、错误证据退回、正确组合盖章；批量核对 2–3 条节奏；主张进快照、撤销不回滚已盖章字段。
- 完成：字段集齐掉落人物线索（落地已捕获）；真名级触发 G14 反白行。
- `mono_audit.py --check` 通过。

## 0. 一句话结论

界面与手感问题前两轮已经收得差不多，这一轮暴露的是更里层的三件事：

1. **有两条 P0 会直接毁掉玩家进度**：「重置」一键删档无确认（K1）；「植物」成功后**不产出「门的后面」场景**，相关结局被硬锁（G2）。
2. **玩家其实没有被教会玩**：三个核心动词写在默认关闭的日志里，首屏没有可见教学（G1）；从「捕获线索」到「推演」的主链没有引导（G4）。
3. **同一动作在不同上下文规则不同**（K 组 11 条），加上**主线程几处可预见的长帧**（F 组），共同构成「不丝滑」的体感。

**G 组核心方案**：

> **内容层架构总纲（2026-10-24 用户拍板）**：`content` 等叙述性文字**只负责纯文字职能**（叙事、节点说明），
> 不再承担任何数据/逻辑作用。所有标签相关职能全部退役；只保留「重看叙事、播放音乐」这类
> 简单的关联功能——正文/节点只声明「关联了哪段叙事、哪首音乐」，播放行为由系统完成，文本本身不参与逻辑。
> 详见文末 §7「标签退役清单」。

- **G1 分步首局引导**（而不是再补一条日志）：做一个常驻的「当前目标」小条（可并入 G6），按状态机推进：
  `双击花园` → `双击书桌/抽屉` → `双击点亮手电筒` → `拖手电筒到黑影` → 首次获得可分析节点时 `拖给 TEC` → 首次捕获时 `拖上推演桌布`（接 G4）→ `长按执行者推演`。
  每步在动作完成前持续可见；顺带教「图标同样双击打开」。引导完成或老玩家读档后永久关闭。
- **G2 内容修复**：`on_success` 实际产出 `SCENES_mdhm` 节点，文案改「新的场景『门的后面』已出现，双击进入」；补一条**从正常首局状态到达该场景及按钮线索的端到端用例**（这类「数据把结局锁死」的问题只有端到端能拦住）。
- **G3 结局引导改道**：toast 改「把桌布上的种子拖到左侧『花园』图标」；或开花园窗时自动错开推演窗，保证种子与花圃同时可见。
- **G5 失败反馈分档**：组合失败给轻量即时提示「没有反应，可查看详情或拖给 TEC」；推演失败区分「尚未放入线索 / 配方不成立 / 有多余线索」，不直接公布答案。
- **G7 TEC 卡关救济**：TEC 提示接入所有首次展开路径；闲聊耗尽后改为按当前状态的分级提示（方向 → 操作 → 较明确答案），不要保留「可闲聊」的假象后静默。
- **G8**：写盘失败留在证件页、可读错误 + 重试；若允许临时身份继续，必须明示「本次不会保存」。

## 7. 标签退役清单（已定，2026-10-24）

**总纲**：`content` 等叙述性文字只负责纯文字（叙事、节点说明）。凡是被解析成数据/逻辑的标签，全部退役；
只保留「重看叙事 / 播放音乐」这类**声明式关联**（正文声明关联对象，播放/重看由系统完成，文本不参与逻辑）。

| 标签 | 现有职能（证据） | 退役去向 |
|---|---|---|
| `[loc:X]` | 场景前往通路（`ComboSystem.gd:65-67`，已随「前往废弃」死掉的半边）；「无文本入口」警告的文本入边统计（`GraphState.gd:805-825`） | 通路删除；入边统计改读 `node_locs` 字段，不再解析正文 |
| `[clue:X]` | 组合/命令成功正文产线索并直接记为已捕获（`ComboSystem.gd:157-170`、`CommandSystem.gd:230`、`GraphState.gd:739-742`） | 并入现行 `hidden_clue` + TEC 分析通道（`SceneDef/ItemDef/CharDef.hidden_clue`），「一切线索经 TEC 之手」与开场教学同构 |
| `[item:X]` / `[char:X]` | 正文中把 id 渲染成显示名（`SceneDef.gd:26` 注释、`CaseLoader.strip_tags`） | 正文直接写显示名；`validate_nodes()` 加一致性校验（清单里的名字与正文出现处核对） |

**保留的声明式关联**（不属于标签退役范围）：重看叙事、重看对话、播放独白、播放音乐——
节点只声明「关联了哪段叙事/哪首音乐」，行为由系统执行。

**统一捕获语义（已定，2026-10-24）**：全游戏只有一个捕获入口——**TEC 分析**。
普通线索与隐藏线索一视同仁：节点携带 `hidden_clue`，拖给 TEC 分析后产出并捕获。
画布「双击线索 = 捕获」废弃（`_capture_clue_node()` 链路退役），双击线索改为查看详情；
「捕获线索 N」计数、卡面 `.got` 深色反白态、日志 `cap` 条目全部由 TEC 捕获路径统一驱动。

   `hidden_clue`；组合成功反馈改为「有可分析的发现」类指引，不再直接给线索。
   例外口径：若个别线索确实要「组合即得不需分析」，加显式结构化字段，不回退文本标签。
   排查对白/回忆路径有无同样从文本产线索的残留。
3. `[item:]/[char:]`：正文换显示名 + 校验落地后，删除 `tags_of` / `strip_tags` 解析器，
   并加一条「正文出现 `[xxx:` 模式即报错」的校验防回灌。

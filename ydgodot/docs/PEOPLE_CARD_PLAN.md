# 人物档案卡设计（名册重构 + 调查员入册）

> 日期：2026-10-25
> 性质：玩法/界面设计文档（2026-10-25 已实施，见 §7）。
> 背景：现 `PeopleWin` 的名册是「导航列表」——点行直接触发跳转/叫人。改为：**点行打开人物档案卡**，
> 跳转降级为卡片内的次级按钮；调查员（玩家自己）一并入册。
> 关联：`UX_FLOW_PLAN.md`（K 组一致性）、`UI_AESTHETIC_PLAN.md`（AvatarFrame 容器语法）、
> `INTERACTION_UX_PLAN.md`（S/W 组不涉及本卡，交互归本文档自定）。

---

## 0. 一句话定位

人物窗从「跳转入口」变成「**一叠档案卡**」：名册是抽屉，卡片是档案。
调查员入册后，「我的证件」也有了常驻的查看位置。气质向 HyperCard 的卡片抽屉看齐。

---

## 1. 字段表

### 1.1 玩家可填写（进存档）

| 字段 | 类型 | 说明 |
|---|---|---|
| 备注 | 自由文本（多行） | 玩家自己的调查笔记（「他在撒谎」「6月2日他不在场？」）。点击即编辑，失焦自动保存，按人物 id 存进存档 |

### 1.2 系统维护（玩家不可编辑）

| 字段 | 来源 | 说明 |
|---|---|---|
| 姓名 | `CharDef` | 卡片标题位 |
| 身份/职业 | `CharDef.desc` 首句或新增短字段 | 字段名取宽：装得下「植物学家」也装得下「陆珩松的助手」 |
| 状态 | 系统推导 | 死者 = 死因（「窒息 · 注射器」）；活人 = 「存活」；可扩展「下落不明」。**每张卡都有内容**，不是可有空洞 |
| 照片 | 头像资源 | `AvatarFrame` 档案照语法（方角 + 1px 键线 + 灰青底），卡片大图与名册缩略图同源 |
| 首次记录 | 系统推导 | 第一次遇见的时刻/场景（「6月2日 · 花园」），侦探档案的灵魂字段 |
| 关联 | 案件数据/推导 | 一句话说明与案件的连接（「本案死者」「植物园主人」），没有则省略该行 |

### 1.3 明确不放的

- **交谈进度 / 已聊完 / 可对话**——玩法状态不进档案（名册行上可保留极轻的状态点，卡片里没有）。
- **「谁认识谁」的关系网**——本案体量用不上，关系由玩家在备注里自己记，这才是侦探游戏的味道。

### 1.4 调查员（玩家自己）

- 常驻名册首位（沿用现有 TEC/执行者常驻的口径，改为其后第一位）。
- 字段复用证件：**姓名 / 编号 / 入职日期 / 照片**；状态行固定「调查员」；无死因问题自然消解。
- 备注同样可写（「我的调查笔记」位）。

---

## 2. 交互

| 动作 | 行为 |
|---|---|
| 点名册行 | 打开该人物的档案卡（**不再跳转/叫人**） |
| 卡片上「前往此人」 | 次级按钮，一步到达（叫人到镜头中央）——原有跳转功能降级保留，不删 |
| 备注区 | 点击即编辑，失焦/Esc 保存收起 |
| 卡片关闭 | × 或点卡片外（待定，见 §5） |
| 同时只开一张卡 | 开新卡即替换旧卡（档案卡是「查看器」，不是窗口管理器里的窗） |

---

## 3. 视觉规格

- **档案卡比例**：竖长，约 260×340（证件比例），直角 + 2px 框（回忆卡同级），1-bit 偏移影（浮层语法，`UI_AESTHETIC_PLAN.md` A4）。
- **布局**：顶部照片（72×72 档案照框）→ 姓名（标题字距）→ 身份/职业 → 1px 发丝线 → 状态行 → 系统档案行（首次记录/关联）→ 备注区（底部，占位文案「写点笔记…」`INK_FAINT`）→ 卡底「前往此人」小键。
- **层级**：档案卡属浮层，高于普通系统窗、低于 Toast（z 档接入现有 rank 体系）。
- 全部在单色纪律内；唯一彩色是照片（内容容器内，合规）。

---

## 4. 数据与存档

- 备注存档结构：`save["notes"] = { "CHARS_zs": "…", "INVESTIGATOR": "…" }`（并入 `SaveSystem` 快照；**撤销不回滚备注**——笔记是玩家的，不是案情的，与日志同口径）。
- 「首次记录」「状态」为推导字段，不落盘。
- 调查员入册的数据源：证件（`Investigator`），无证时不出现（开场流程完成前名册本就不开）。

## 5. 待定问题

1. **卡片关闭方式**：× 按钮、点外部关闭、还是 Esc？建议三者都支持（Esc 属 INTERACTION_UX_PLAN W11 键盘批）。
2. **状态字段的数据源**：死因目前数据里有吗？若没有显式字段，初期可用「存活/死亡」二分，死因文字进 `CharDef` 新增可选字段，由案件数据填写。
3. **TEC 与执行者的卡**：常驻两人是否也给档案卡（TEC 的「身份」= AI 助手，状态行写什么）？建议给，保持名册语义统一。
4. **名册行上的轻状态点**保留与否（「可对话」圆点）——建议保留，它是列表层的唯一玩法信息。

---

## 6. 验收要点

- 点名册行只开卡，不跳转；「前往此人」一步可达原行为。
- 备注写入 → 读档后仍在；撤销不回滚备注；换案不串档（备注按案件存档隔离）。
- 调查员在册，字段与证件一致；死者卡的状态行显示死因，活人显示存活。
- 每张卡高度恒定、无撑跳（沿用 DetailWin 的响应式贴合经验）；卡片不出视口。
- 无头断言：点行开卡、备注读写回环、调查员入册、死者/活人状态分支。

## 7. 实施记录（2026-10-25）

- 新增 `scenes/windows/PersonCard.gd`：260×360 竖卡、2px 框 + 偏移影、照片 / 姓名 / 身份 / 状态 / 首次记录 / 关联 / 备注 / 次级动作；`ZR_PERSON=27`，高于普通系统窗、低于 TEC / toast。
- `PeopleWin` 点行改为只开卡；调查员常驻首位；TEC / 执行者 / 调查员 / 普通角色共用同一套卡。`_on_people_row` 不再跳转，跳转降级为卡内「前往此人」。
- 备注：`GraphState.notes` 按人物 id（调查员用 `INVESTIGATOR`）存；进入 `SaveSystem` 快照；撤销时 `restore(keep_knowledge=true)` 不覆盖，读档按存档恢复；换案由新 `GraphState` 自然隔离。
- 状态：`CharDef` 新增 `role / fate / relation`；A-001 五名角色已填。陆珩松 `死亡 · 吊颈`，其余存活；TEC 在线、执行者待命、调查员在册。
- S12 顺带收口：对话窗开着时「前往此人」只把对话提层，不再误报「暂无对话文本」。
- 验证：`test_p26` 135 项、`test_p15` 102 项；全套 1610 项、`test_p28` 4/4、`mono_audit` 通过。
- 未做：点卡片外关闭（§5.1 待定；当前支持 × / 卡内 Esc 保存收起）。

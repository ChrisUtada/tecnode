# UI 高审美优化计划（复古早期 macOS 方向）

> 日期：2026-10-23
> 范围：全界面视觉与审美 —— 桌面/顶栏、窗口系统、节点卡片与画布、色彩纪律、排版层级、控件细节。
> 证据：`docs/p0_*` ~ `docs/p2_*` 全套截图、`assets/raw/*-avatar.png`、`ui/TecTheme.gd`、`scenes/windows/SysWindow.gd`。
> 关系：`UI_POLISH_AUDIT.md`（U1–U8，已完成）修的是「看起来像坏了」的控件几何问题；
> 本文档处理的是**体系级审美**——层次、秩序、纪律、气质。
> 优先级：**P0 = 明显的视觉事故**；**P1 = 破坏体系一致性**；**P2 = 审美提升（从「能用」到「讲究」）**。

---

## 0. 一句话结论

单色骨架（墨/纸分层、12px 点阵字、键线语法）已经立住，**底子是对的**；当前的问题集中在四类：

1. **层次缺失**：窗口无前后景之分、无投影、无激活态，平铺在白桌面上像一叠散纸。
2. **纪律破窗**：彩色头像裸贴在单色窗里（没有容器语法）、音乐窗大面积黑药丸，彩色与黑块都缺自己的规矩。
3. **秩序松散**：顶栏调试按钮混排、卡片大小不一且对齐随意、列表行高与截断不统一。
4. **细节事故**：TEC 窗文字重叠、矩阵窗下挂空矩形、日志窗漏调试文本「组合 item:IT」、人物窗末行被裁。

## 2. 分项说明与优化方案

### A. 顶栏与窗口系统

**A1 顶栏调试工具收纳（P0）**
顶栏是玩家第一眼看到的「系统门面」，现在右侧 7 个调试开关（合成消耗/聚焦选中/新节点自动居中/适应窗口/撤销/重置/检查可达性）暴露了开发态。
- 保留：品牌 `T.E.C·OS`、证章 `1212 · TEC-RB-5322`。
- 调试项全部收进一个「调试」下拉/弹出面板（`header_button` 语法，黑底白字统一）。
- 「撤销」若是正式玩法则保留为正式按钮（键线语法），否则一并收纳。
- 涉及：`scenes/Desktop.gd` 页眉构建段（约 `_build_header` / `_check_tex` 一带）。

**A2 激活/非激活窗口态（P1）**
System 6 的经典语法：激活窗标题栏有条纹、非激活窗标题栏留白。当前所有窗标题栏都是条纹（`SysWindow._title_rule()`），多窗重叠时无层次。
- 激活窗：条纹 + 2px 框（现状）。
- 非激活窗：隐藏条纹、框降为 1px、标题色用 `INK_FAINT`。
- Desktop 的 z-rank 插队处同步通知各窗刷新激活态。

**A3 弹窗圆角收口（P1）**
`IntroWin` 头像选择等弹窗用 r≈10 大圆角，系统窗是 `R_WIN=0`。按 `TecTheme` 圆角分级，模态弹窗应回归方角（或至多 `R_SM=5` 的「面板」档），全文统一。

**A4 1-bit 投影（P2）**
不用模糊阴影（违背 1-bit），用经典 Mac 的**实心偏移影**：窗体右下偏移 3px 的纯黑实块（菜单/窗口在 System 1–6 的做法）。只给浮层（弹窗、菜单、Toast）用，普通窗保持平面，避免满屏黑边。
- 实现：`SysWindow._build_shader_bg()` 增加可选 `offset_shadow` 层；配色走 `TecTheme.shadow(1.0)`。

**A5 TEC 对话窗排版（P0）**
现状：头像下文字行重叠、横线穿字、下半窗全空。
- 重排为三段的固定节奏：头像+名字（左 60px 栏）/ 状态短句（右）→ 1px 分隔线 → 对话区 → 底部提示行。
- 空态给一句居中的 `INK_FAINT` 占位文案，而不是留白。
- 涉及：`scenes/windows/TecWindow.gd`（头像区 `_avatar` 60×60 一带）。

**A6 列表行裁切/溢出（P0）**
- 所有列表行固定行高（建议 24px 网格），内容垂直居中；行高不足时窗口 `content_min_height()` 兜底逻辑已存在，需排查 `PeopleWin`/`StorageWin` 的行构造为何超界。
- 按钮（如「取回」）放进行的固定右栏，行宽 = 窗宽 − padding − 滚动条宽。
- 涉及：`scenes/windows/PeopleWin.gd`、`StorageWin.gd`、`SysWindow.content_min_height()`。

**A7 矩阵窗残留空矩形（P0）**
`MatrixWin` 窗体下缘外有一无内容矩形。定位并移除（疑似某个未删的占位 Panel/进度条）。涉及：`scenes/windows/MatrixWin.gd`。

### B. 色彩纪律

**B1 彩色内容层规范（P1，2026-10-23 修订：头像保留彩色）**
原「头像单色化」方案作废——头像和后续的彩色 CG 是**内容**，不是界面铬件。问题从来不在彩色本身，而在彩色没有自己的容器语法：头像裸贴在单色窗里，才显得破窗。
- **总规矩：UI 铬件一律单色；彩色只允许出现在「内容容器」内**——头像框、CG 装裱框、记忆卡插图区。容器之外不溢出任何彩色。
- **头像 = 档案照语法**：固定格（列表 48×48 / 详情 72×72）、1px INK 键线框、方角、统一底色（用 `BG` 灰青打底，不用透明底）。不同来源的像素头像套进同一套框，就是一版统一的证件照，彩色反而成了「内容层」的标识。
- **头像间的协调**：新头像走同一明度/饱和度区间（中明度、中低饱和）；现有 `executor-avatar` 红粉偏艳，建议降饱和 20–30%，避免一张高饱和红脸压过整屏。
- **CG 规范**（后续加入时照此施工）：CG 只出现在专用容器（记忆卡 / 结局 / CG 查看器），「拍立得」式装裱——纸面底 + 1px 键线内框 + 下方一行图注（`INK_FAINT`）；CG 不加滤镜、不做窗口背景、不铺出容器边缘。
- 实现上做一个统一的 `AvatarFrame` / 内容框组件，替换 7 处裸贴的 `TextureRect`：`ChatWindow.gd`、`MemCard.gd`、`PeopleWin.gd`、`TecWindow.gd`、`TecChip.gd`、`IntroWin.gd`、`MatrixWin.gd`。

**B2 音乐窗黑药丸（P1）**
曲名「Air (Bach)」用整条纯黑 pill，是窗内最大的一块黑。改为：白底 + 1px 键线行 + 左侧小音符 glyph；播放中态用**行内反白小方块**或进度条本身表达，不整行填黑。涉及：`scenes/windows/MusicWin.gd`。

### C. 画布与节点卡片

**C1 「新」角标重做（P1）**
现状是纯黑圆球压住卡片右上外角，读作「污渍」。改为：卡片**内右上**的药丸小牌（白底黑字 + 1px 键线，`R_PILL`），或卡片上缘外侧居中挂牌。未读语义同时体现在 Dock 徽章上（已有），卡片角标可以更轻。
- 涉及：`scenes/cards/NodeCard.gd`（角标构造段，U4 已改过一轮尺寸）。

**C2 连线图例（P1）**
约定并文档化三种线，且在 `EdgeLayer` 一处实现：
- 已连通/已探索：1px 实线（INK）。
- 可连未试：1px 灰线（`edge(0.3)`）。
- 试过未成：1px 虚线（`EDGE_TRIED`）。
- 拖动中：2px 实线 + 末端箭头。
当前黑/灰/曲/直混用，需逐态核对。涉及：`scenes/canvas/EdgeLayer.gd`。

**C3 网格与卡片节奏（P2）**
- 卡片吸附 8px 网格；同一场景的卡片统一宽度档（如 96/128/160 三档）。
- 类型 glyph（`KindGlyph`）从 ~8px 提到 10–12px，五种形状在 12px 格内重绘，确保 1x 下可辨。
- 涉及：`scenes/cards/NodeCard.gd`、`ui/KindGlyph.gd`、`scenes/Desktop.gd` 摆卡逻辑。

### D. 排版与信息层级

**D1 只有 12px 时的层级手段（P1）**
字号被点阵字锁死（12 的整数倍），层级只能从这几个轴出：
1. **反白**：窗口内小节标题用黑条白字（h4 级）。
2. **字距**：窗口标题/品牌用 +1~+2 glyph 间距（`brand_font()` 已有）。
3. **明度**：注释/占位用 `INK_FAINT`，正文用 `INK`（对比档位已验证，沿用即可）。
4. **线**：小节之间 1px 分隔线，段落之间 6px 空（`NARR_LINE_SPACING`）。
约定成 4 级：窗标题（字距+条纹）> 节标题（反白条）> 正文 > 注释（FAINT），写进本文档即生效，新窗口照此施工。

**D2 列表行规范（P1）**
- 行高统一 24px；行间 1px `edge(0.18)` 发丝分隔线（不顶格，左右留 8px）。
- 截断一律 `OVERRUN_TRIM_ELLIPSIS` + tooltip 显示全名（档案窗、人物窗）。
- 空列表给占位文案（`INK_FAINT`），不留大白板（证物袋、花园的现状）。
- 涉及：`ArchiveWin.gd`、`PeopleWin.gd`、`StorageWin.gd`、`GardenWin.gd`。

**D3 日志窗净化（P0）**
- 过滤调试条目（「组合 item:IT」这类内部 key 不进玩家可见日志；保留进 `user://` 调试日志文件）。
- 条目与窗口右缘留出滚动条宽度 + 4px 内边距。
- 涉及：`scenes/windows/LogWin.gd`、`core/` 日志写入处。

### E. 桌面与细节收口（P2）

- **E1 桌面焦点**：平涂灰保留（`TecTheme` 已论证网点不可行），但在桌面中心偏上压一个 3–5% 浓度的 TEC 水印 glyph（`scrim(0.04)` 级），空旷时给视线一个锚点；窗口多时自然被遮。
- **E2 Dock 秩序**：图标统一 44×44 格、等距（建议 12px）、标签基线对齐；徽章一律右上角外贴 −2,−2。
- **E3 音乐控件**：⏸/■ 换成 `TecTheme.button()` 语法的小方键（18×18，glyph 自绘不依赖字体基线，沿用 U2 的结论）。
- **E4 Toast**：固定右下角、距边 16px、黑底白字 pill、停留 2.4s 淡出；同屏最多 1 条，后来的排队。

## 4. 纸色改版：仪器灰青（F1，2026-10-23 定稿）

**诉求**：纯白纸面刺眼；但不要暖黄纸张感，要复古科技味；不要赛博朋克式的花花绿绿。

**定稿方向：B · 仪器灰青** —— 老式示波器 / 实验室仪器的面板色：极淡的青绿冷白做纸，灰青做桌面。
气质上把界面从「一张纸」变成「一台 T.E.C 调查设备」，与设定贴合；青绿浓度压到「不说看不出、说了能感到」的级别，不会滑向彩色界面。

**Token 映射**（只动 `TecTheme.gd` 调色板段，调用方零改动；`mono_audit.py --check` 不受影响）：

| Token | 现值 | 新值 | 说明 |
|---|---|---|---|
| `CARD` / `PAPER` / `FACE_HI` / `FACE_LO` / `FACE_RISE` / `MEM_*` | `#FFFFFF` | **`#EDF1EE`** | 纸面：一丝青绿的冷白 |
| `DESK_GRAY` | `#EFEFEF` | **`#C4CCC6`** | 桌面：灰青，**加深以拉开窗/桌层次** |
| `BG`（外壳/dock 底板） | `#FFFFFF` | **`#DCE2DD`** | 介于纸与桌之间的一档，外壳读作「框」 |
| `INK` / `INK_MUTED` / `EDGE` / 深色反白面 | 不变 | 不变 | 墨色保持纯黑；1-bit 里没有灰墨的位置 |
| `TEXT_ON_DARK` `#F0F0F0`、`SPOT_*` 专色 | 不变 | 不变 | 点亮金在灰青底上仍需截图复核光晕 |

**为什么这个组合成立**：

- **刺眼来自「满屏最亮」而非白色本身**：纸面从 100% 亮度降到 ~93%，桌面从 #EFEFEF 加深到 #C4CCC6，
  「窗浮在桌上」的明度差从 1.09:1 拉大到 **1.43:1** —— 窗口反而比现在更「浮」，同时全屏不再有纯白。
- **对比度仍达标**：INK 对新纸面 ≈ 18.3:1（原 21:1），正文余量充足；`INK_FAINT` 仅作装饰用途的定位不变
  （若在新纸面上偏淡，允许降到 `#808080`，在批次 5.5 验收时判定）。
- **不是暖黄纸**：色相落在青绿（~150°），与「做旧纸」（~50° 暖黄）在色环上相反，规避了拟物感。
- **不是赛博朋克**：全屏仍是黑/灰青两色的 1-bit 纪律，青绿只存在于底色的 ~4% 饱和度里，没有任何高饱和专色铺开。

**验收**：

- 960×560 / 1280×720 / 1920×1080 三档截图：无纯白大面积、无暖色残留、窗/桌层次清楚。
- 核对 `assets/baked/`（`stage_paper.png` 等）是否有按旧白/暖色烘焙的贴图，有则随批重烘。
- 点亮态金光晕（`SPOT_LIT_HALO`）在灰青纸面上不发脏；发脏则把 HALO 往中性调一格。
- 全套无头测试（1168 项基线）保持全绿；`tools/mono_audit.py --check` 通过。

## 5. 本轮不做

- 除 §4 已定稿的纸色改版外，不动墨/线/专色其余部分；「专色 ≤9px」红线按 B1 修订为：**UI 铬件单色，彩色只允许出现在内容容器（头像框 / CG 装裱框）内**——动工前先同步修订 `MONO_REDESIGN_PLAN.md` §4.3 的表述。
